# SNS投稿文ミニループウェア　準備と使い方

キーワードを入れると、SNS投稿文が3案出ます。案ごとに「良い／悪い」「直す」「理由」を残すと、その記録（判断のログ）からAIが「学び（ルールの案）」を出し、採用したルールが次の3案から効きます。ログが溜まるほど、AIへの指示（プロンプト）が育ちます。

- 必要なもの：Node.js（20以上）だけ。ほかに入れるものはありません
- データ（ログ・ルール）は、使う人のブラウザにだけ残ります。サーバーには何も保存しません

---

## 手順1　Node.js があるか確かめる

1. 「ターミナル」を開きます（Mac：Launchpad →「その他」→「ターミナル」）
2. 次を貼って、Enter を押します

   ```bash
   node -v
   ```

3. `v20.` 以上の数字（例：`v22.11.0`）が出れば大丈夫です
4. 「command not found」と出たら、Node.js が入っていません。https://nodejs.org/ja から「LTS」と書かれた版を入れて、ターミナルを開き直してから、もう一度2をやります

## 手順2　自分用の設定ファイル `.env.local` を作る

設定は、このフォルダ（`loopware-mini`）の中の `.env.local` というファイルに書きます。見本は `env.example` です。

**大事：APIキーは、お金がかかる合鍵です。** このファイルの中身は、AI（Claude Code など）との会話・スクリーンショット・SNS・メモに貼らないでください。AIにも開かせません。

### 2-A　まずはAIを使わずに試す（ダミー出力。キーが無くても動きます）

1. ターミナルで、このフォルダに移動します（`cd` のあとに、フォルダのある場所を書きます）
2. 次を貼って Enter を押すと、`.env.local` ができます（中身は2行だけ。キーは使いません）

   ```bash
   printf 'LLM_PROVIDER=mock\nEVENT_PASSCODE=test\n' > .env.local
   ```

   - `LLM_PROVIDER=mock`：本物のAIを呼ばず、決まった文を返します
   - `EVENT_PASSCODE=test`：画面に入るときの合言葉です（好きな文字に変えてかまいません）

### 2-B　本物のAI（Anthropic）を使う

1. https://console.anthropic.com でAPIキーを作ります
   - **先に、月の利用上限（金額）を小さく設定してください**（例：5ドル）。漏れたときの被害を小さくするためです
2. 次を貼って Enter を押すと、メモ帳（テキストエディット）で `.env.local` が開きます（無ければ見本から作ります）

   ```bash
   [ -f .env.local ] || cp env.example .env.local; open -e .env.local
   ```

3. 開いたファイルを、次の形にして保存します（`LLM_API_KEY=` の右に、自分のキーを貼ります。ここだけに貼ります）

   ```text
   LLM_PROVIDER=anthropic
   LLM_API_KEY=（ここに自分のキー）
   EVENT_PASSCODE=（好きな合言葉）
   ```

   - モデルの指定は不要です（3案は Claude Haiku 5.5、学びの抽出は Claude Sonnet 5.5 が自動で使われます）
   - OpenAI や OpenRouter を使うときは、`LLM_PROVIDER=openai`（または `openrouter`）にして、`LLM_MODEL_GENERATE=` と `LLM_MODEL_IMPROVE=` にモデル名を必ず書きます
4. 起動していたら、一度止めて（手順4）、もう一度起動します。設定は起動のときに読み込まれます

もしキーをどこかに貼ってしまったら：提供元の管理画面で、そのキーを無効にして作り直してください。

## 手順3　起動する

1. ターミナルで、このフォルダにいることを確かめます
2. 次を貼って Enter を押します

   ```bash
   npm start
   ```

3. 「起動しました」と出たら、ブラウザで http://127.0.0.1:3000 を開きます
4. 合言葉（`EVENT_PASSCODE` に書いた文字）を入れて「入る」を押します

このサーバーは、自分のパソコンの中だけで動きます。同じWi-Fiの他の人からは開けません。

## 手順4　止める

起動したターミナルで、`Ctrl` と `C` を同時に押します。

## 手順5　使い方の流れ

1. **出す**：キーワードを入れて「3案を作る」
2. **選ぶ**：3案それぞれに「良い／悪い」、理由のタグ、一言。直したい案は「直す」で本文を書き換えます（保存ボタンはありません。すぐ保存されます）
3. 次のキーワードで、また3案。判断を残した回が3回たまると、「プロンプトを改善」が光ります
4. **育てる**：「プロンプトを改善」を押すと学習ステージが開き、ログから学びが出ます。活かしたいものに「次回以降に活かす」
5. **効かせる**：右の「いまのプロンプト」にルールが足され、次の3案から効きます

そのほか

- 右上「↶ 一つ前に戻す」：直前の操作を1つずつ取り消します（`Ctrl`／`⌘` + `Z` でも同じ）
- 右上「ゼロから再スタート」：いまの学習を「保存した学習」に残して、最初からやり直します
- 右上の時計のボタン：「保存した学習」を開いて、前の学習に戻れます（12件まで）

## 困ったとき

1. **「ポート3000は、ほかのものが使っています」と出る**
   別の番号で起動します。`PORT=3001 npm start` と打ち、http://127.0.0.1:3001 を開きます
2. **「合言葉が違います」と出る**
   `.env.local` の `EVENT_PASSCODE=` の右と同じ文字を入れます。`.env.local` を直したら、起動し直します
3. **「ただいま準備中です」と出る**
   `.env.local` に `EVENT_PASSCODE=` が無いか、右が空です。手順2をやり直して、起動し直します
4. **「AIの呼び出しに失敗しました」と出る**
   - キーが無い・間違っている・利用上限に達した、のどれかが多いです。起動したターミナルに `[llm] 設定が足りない` や `status=401` などが出ていないか見ます
   - 少し待ってから、もう一度押します。キーが用意できないうちは、手順2-Aのダミー出力で試せます
5. **画面が真っ白／古いまま**
   ブラウザで再読み込み（`⌘` + `R`）します
6. **ログを消して最初からにしたい**
   右上「ゼロから再スタート」を使います（前の分は「保存した学習」に残ります）

## 公開したいとき（任意）

手元で動けば、公開は必須ではありません。イベントで他の人にも使ってもらいたいときだけ、Vercel（無料で始められる公開サービス）で公開できます。

1. AIに「公開したい」と伝えてください。GitHub と Vercel のアカウントの有無、入っているツールを聞いたうえで、あなたに合った手順を案内します
2. 公開するときの約束
   - キーは、Vercel の「Environment Variables（環境変数）」の画面に入れます。ファイルに書いて上げません
   - `EVENT_PASSCODE` は、他人に推測されにくい文字にして、使う人にだけ伝えます
   - `.env*`・この `SETUP.md`・`dev-server.js` は、`.vercelignore` で公開物から外してあります

## ファイルの役割（参考）

| ファイル | 役割 |
|---|---|
| `public/index.html` | 画面（1ファイル） |
| `api/generate.js` | 3案を作る |
| `api/improve.js` | ログから学び（ルール案）を作る |
| `api/_shared.js` | 合言葉の確認・回数制限・AIの呼び出し |
| `dev-server.js` | 手元で動かす小さなサーバー |
| `env.example` | 設定の見本（値は空） |
