# 資料の案づくり・振り返りの型（エージェント用・正本）

Nody `/slides` に置くデッキ（`docs/slides_deck_sample.json` の形）を作るときの決まり。ツールの中で自動学習はしない。採否は松野さん。

## 作る前（stage = plan）

1. `slides_loop.py state` で **資料の基準（採用済み）** と前回選んだ内容を読む。
2. 構成案は **3つ**（2〜4可）。毎回、主題の置き方が違う3つにする（事例中心／新技術中心／教育中心 など）。
3. 各案の `applied` に、その案で効かせた基準の id（`<デッキid>:<反映案id>`）を入れる。画面に「前回の学びを反映：…」と出る。採用済みの基準は、**どの案にも**効かせる（外すときは note に理由）。
4. 観点 `axes` は既定の4つ（分量・トーン・図の量・今村さん課題）。前回選んだ値を ★（recommended）にする。
5. 3案の並びは毎回入れ替えてよい（並び順もログに残る）。

## 作った後（stage = review）

1. 直す前（エージェントが出した版）と直した後（松野さんの版）を `log-fix` で記録する。打ち間違いの直しは `--intent typo` で分ける。
2. 直しを **概念** にまとめ、次回反映案を 2〜5件 作る。1件ごとに
   - `concept`：まとめた概念（例：用語の言い換え／事例の型／分量）
   - `text`：次回に効かせる基準の文（1文）
   - `why`：根拠（今回どこを何か所どう直したか）
   - `evidence`：直しの例を2〜3個（前 → 後、短く）
3. 1回だけの直しは「見直す候補」として出してよいが、断定しない。2回以上同じ直しが出たら「次からも？」として強めに出す（L03）。
4. すでに採用済みの基準と同じものは出さない。食い違うものは「取り消し候補」と書く。
5. 顧客名・個人名・金額は伏せる。
