# KURASHIFT 検証プラン（ユーザー実行サイクル）

プラン末尾 To-do: **`verification-with-user`**

## この検証で見るもの

技術単体テストではない。**今回の実装全体**について、あなたがアプリ側から操作し、

> 提案 → 確認 → キュー → Mac 実行 → 画面に結果 → 次の一手

のサイクルが回るか（＝実務でエグゼキューションできるか）を見る。

Jarvis は実装を先に終え、ここで指摘どおり直す。うまくいかない点はその場で伝えてよい。

---

## 合格の定義（全体）

次の5つを、自分の操作だけで説明・完了できること。

| # | できること |
|---|---|
| 1 | **秘密を入れて**、週次で資産と保険借入が見える |
| 2 | **トップ／テーマ**で提案→承認→完走アシストまで回せる（実弾は出ない） |
| 3 | **ライフプラン**で実績→ギャップ→CSV／（明示時のみ）Zaim まで回せる |
| 4 | **個人申告**で弥生CSV作成と証憑取込が一覧に出る |
| 5 | どこで止まったか・次に何を押せばよいかが画面上わかる |

**前提（初回だけ）**

- ローカル: `http://localhost:3003` または本番 Vercel
- Mac でジョブ worker が動く（画面の「キューに入れた」だけでは裏が走らない）
- ログインは Jarvis ダッシュボードと同じアカウント

```bash
# 詰まったときの補助（本線はアプリ操作）
cd ~/git-repos && ~/selenium_env/venv/bin/python scripts/jarvis_kurashift_job_worker.py --once
```

## 推奨の通し順（初回は半日〜1日想定）

```
A セットアップ → B テーマ1本 → C LP年次（軽く） → D 申告ドラフト → E 日常イメージ → F 境界
```

途中で止まったらそのサイクル番号だけ Jarvis に返す。全部一度に終わらせなくてよい。

## サイクル A — 初回セットアップ（設定→見える化）

**シナリオ**: 初めて開き、口座ログインを入れ、資産と保険借入が画面に出るまで。

| # | あなたがやること | 期待する結果 | 実装の対応 |
|---|---|---|---|
| A1 | `/login` でログイン | 「KURASHIFT」表示→ホーム | ブランド |
| A2 | **設定**でソニー／Bloomo／PRU 等を入力→保存 | 「キューに入れました」。値は画面に残らない | secrets |
| A3 | ジョブで `secrets_upsert` 成功を待つ | 設定の「登録済」が増える | worker |
| A4 | **資産**「週次スナップをキュー」 | Core 網羅・保険借入に数字 | portfolio weekly |
| A5 | 保険借入額を自分の認識と照合 | 合えば OK | 契約者貸付 |

止まったら: ジョブ失敗理由・未設定キー・Mac版LINEと無関係（ここはブラウザログイン系）。

---

## サイクル B — テーマ投資（提案→承認→実行準備）

**シナリオ**: トップ中心で「投資テーマを1本、承認まで進める」。証券の実発注はしない。

| # | あなたがやること | 期待する結果 |
|---|---|---|
| B1 | **テーマ**「ステータスから提案」または「年1RBカードを確保」 | draft が増える |
| B2 | 「相談中へ」→「承認」（確認ダイアログ） | approved |
| B3 | 「プレビュー」「完走アシスト」 | 手順がメモに残る。**発注されない** |
| B4 | ホームにテーマ導線がある | トップ＝提案・実行の中心 |

止まったら: 遷移ボタンなし／ジョブ denied。

---

## サイクル C — ライフプラン年次（実績→判断→財務）

**シナリオ**: 年1〜3回の更新を、画面から一通り踏む（Numbers の手直しは手元でよい）。

| # | あなたがやること | 期待する結果 |
|---|---|---|
| C1 | `/lifeplan?mode=annual` | 年次モード＋段階 UI |
| C2 | Step1「年度実績を取り込む」 | αβγ・19不動産・教育が出る |
| C3 | Step2「予算を補正する」 | 目標との差が分かる |
| C4 | **ROI** で CF／返済を見る | 大きな買い物の感覚がつく |
| C5 | Step4「実行キュー」（confirm なし） | CSV まで。**Zaim 本番は押さない**／明示時だけ本番 |

止まったら: サマリー空・ゲージ空・比較表空。

---

## サイクル D — 個人申告（CSV・証憑）

**シナリオ**: 確定申告シーズン前に、個人分のドラフトと証憑をアプリから揃える。

| # | あなたがやること | 期待する結果 |
|---|---|---|
| D1 | **個人申告**「1. 弥生CSVを作る」 | 案件に csv_ready・パス |
| D2 | 「2. 税理士メールを取り込む」 | 証憑一覧に行（該当年にメールがある場合） |
| D3 | 必要なら行の「証憑出力」 | ローカルに再保存 |
| D4 | 弥生本登録は**しない** | 承認なし本登録が走っていない |

止まったら: Gmail token・ヒット0・パス権限。ヒット0はクエリ／年の問題として Jarvis へ。

## サイクル F — やってはいけない境界

- [ ] 未承認のまま売買・振替が動いていない
