# Grok アプリ開発統括 — 設計（2026-08-24）

## 方針

- **新部署**（不動産・家族とは分離）
- Bot は当面 **統括1のみ**（アプリ別社員は後続）
- **実装・デプロイ・秘密は Jarvis**（統括はリポを直接触れない）
- Supabase: Q&A=`kamiooya-qa`、ダッシュ／KURASHIFT投影=`jarvis-dashboard`（3つ目PJ禁止）
- 週次提案は **全部拾わない**。カード化した分＋松野が指したものだけ

## 分業

| 誰 | 役割 |
|---|---|
| アプリ開発統括（Grok） | 週次レビュー・仕様詰め・**Jarvis向けカード**（材料／実装） |
| Jarvis（Mac） | 週次パック作成・低リスク即実装・高リスクは確認後・コミット／デプロイ |
| 松野 | 「やってみたい」／高リスクの OK／優先の指差し |

## フロー（確定）

```
① Jarvis: git／PR／docs の短い週次パック（未実装→今後）
② 統括ルーティン or 会話: 週次レビュー ＋ Jarvis向けカード（最大3）
②b 統括: estate へ件名 [Grok開発] メール（カード全文。チャンネルだけでは Jarvis 不可読）
③ 朝バンドル jarvis_morning_mac_refresh → jarvis_app_dev_cards_morning.py
   · 低・未処理を要約
   · 高・要承認を列挙
④ Jarvis（対話）:
   · リスク低 → 「やって」で実装可
   · リスク高 → 松野確認後
⑤ 完了を1行で返す（--mark-prompted で消化）
```

小回り: チャンネルで「やってみたい」→ 統括が実装カード＋`[Grok開発]` メール → 朝要約 or その場で「やって」。

不動産の「メールで材料を渡す」に相当するのは、ここでは **📎 Jarvis向けカード＋`[Grok開発]` メール**。  
フォールバック: `.jarvis_state/app_dev_cards_inbox.md` にチャンネル全文を貼っても可。
