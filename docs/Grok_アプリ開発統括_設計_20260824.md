# Grok アプリ開発統括 — 設計（2026-08-24）

**更新**: 2026-09-23（Todoist `#アプリ開発` 自動起票を追加）

## 方針

- **新部署**（不動産・家族とは分離）
- Bot は当面 **統括1のみ**（アプリ別社員は後続）
- **実装・デプロイ・秘密は Jarvis**（統括はリポを直接触れない）
- Supabase: Q&A=`kamiooya-qa`、ダッシュ／KURASHIFT投影=`jarvis-dashboard`（3つ目PJ禁止）
- 週次提案は **全部拾わない**。カード化した分＋松野が指したものだけ
- **人が見るタスク正本は Todoist**（`#アプリ開発`）。GitHub は実装キュー（PR／Issue）

## 分業

| 誰 | 役割 |
|---|---|
| アプリ開発統括（Grok） | 週次レビュー・仕様詰め・**Jarvis向けカード**（材料／実装／表確認）。**PRは切らない** |
| Jarvis（Mac／Cloud） | メール取込・**Todoist 起票**・朝要約・**低=Cloud→PR／高=Issue／表確認=UI確認**・委任マージ・デプロイ |
| 松野 | 「やってみたい」／高リスクの OK／PR の目視または委任 |

## フロー（確定・第1段キュー）

```
① Jarvis: git／PR／docs の短い週次パック（未実装→今後）
② 統括ルーティン or 会話: 週次レビュー ＋ Jarvis向けカード（最大3）
②b 統括: estate へ件名 [Grok開発] メール（カード全文。チャンネルだけでは Jarvis 不可読）
②c Mac launchd（bucho-inbox-poll・起動時＋最大15分）:
      jarvis_app_dev_todoist_sync.py → Todoist lane `apps`（#アプリ開発）へ起票
      · 実装・高 → セクション「オーナー確認」＋ラベル 要ボス
      · 実装・低 → 未着手＋quick／要Jarvis連携
      · 材料／表確認 → 未着手＋要Jarvis連携
③ 朝バンドル jarvis_morning_mac_refresh
   a) jarvis_app_dev_cards_morning.py … 低／高／材料／表確認の要約
   a2) jarvis_app_dev_todoist_sync.py … 取りこぼしがあれば Todoist 起票
   b) jarvis_app_dev_queue.py
      · リスク低 → Cursor Cloud Agent（autoCreatePR）→ GitHub に PR が溜まる
      · リスク高 → gh issue（label: app-dev, risk-high）※自動マージしない
      · 材料 → gh issue（label: app-dev, material）
      · 表確認 → gh issue（label: app-dev, ui-check）※Cloudしない。Jarvisが画面確認
④ 松野: Todoist／GitHub Open PR／Issue を見てマージ・クローズ、または
   Jarvis に「委任して #N」（低PRのみ --merge-pr）
⑤ 高Issue は OK 後に「この Issue で PR 作って」→ Cloud／対話
⑥ 表確認Issue は Jarvis がログインして該当画面を見、結果を Issue／チャットへ
```

小回り: 「やってみたい」→ 統括が実装カード＋`[Grok開発]` → **Mac 起動中なら最大約15分で Todoist**。PR／Issue は次の朝キュー（または手動 queue）。

不動産の「メールで材料を渡す」に相当するのは **カード＋`[Grok開発]`**。  
ホークの「要ボス → Drive `todoist_tasks` → launchd」に相当するのは **同じ launchd 帯で `[Grok開発]` → Todoist apps**（入口がメールなだけ）。

フォールバック: `.jarvis_state/app_dev_cards_inbox.md` にチャンネル全文を貼っても可。

## 表確認（2026-08-28・3アプリ共通）

| 項目 | 正 |
|---|---|
| 対象 | **神大家Q&A** / **Jarvisダッシュ** / **KURASHIFT**（怪しさがあるアプリだけ） |
| 統括 | 週次で各アプリの **裏** を見る。怪しさ → `📎 Jarvis向け（表確認）` |
| Jarvis | `.env.jarvis_private` 等でログインし **表**を確認。結果を返す |
| 禁止 | Drive／メール／カードに ID・パスワードを書く。Grok に本番ログインさせない |
| 上限 | 週次カード合計最大3（表確認もその枠内。無理に3アプリ分出さない） |

裏の見方（目安）:

| アプリ | 裏 | 表（Jarvis） |
|---|---|---|
| 神大家Q&A | Supabase `kamiooya-qa`・知識件数／埋め込み | 本番検索・チャット UI |
| Jarvisダッシュ | Supabase `jarvis-dashboard`・ウォッチ件数など | `/` `/zaim` `/watch` 等 |
| KURASHIFT | deals／投影・docs | `/realestate/deals` 等 |

```
週次（統括・裏）
  → 怪しさあり（アプリごと）
  → [Grok開発] に 表確認カード
  → launchd: Todoist apps 起票
  → 朝: Issue label ui-check
  → Jarvis: 画面確認 → 一致／不一致を報告
```

## リスク帯

| 帯 | 例 | 運用（第1段） |
|---|---|---|
| 低 | 文言・表示・軽いUI・docs | Todoist 未着手。朝で Cloud→PR。**自動マージはしない**（目視 or 委任） |
| 高 | DB／認証／対外送信／課金／大きい挙動 | Todoist オーナー確認＋要ボス。Issue のみ。OK 後に PR |
