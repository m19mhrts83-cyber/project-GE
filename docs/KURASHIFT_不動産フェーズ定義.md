# KURASHIFT 不動産賃貸フェーズ定義（1枚・正本）

2026-10-27 作成。共有用の図つき版: Claude Doc「不動産賃貸フェーズ定義（1枚）」 https://claude.ai/artifact/6WFKE117P1oi4a8d2JzQCb

不動産賃貸を 8 フェーズの一周で定義する。各フェーズは「入口に入った案件を、判断基準で仕分けて、出口に出す」だけを担う。

| フェーズ | 入口 | 出口 | 判断基準 | 画面 / AI社員 |
|---|---|---|---|---|
| 1. 計画 | 年初、物件取得・借換えの後 | 種別・件数・予算・融資先が決まった買い進めプラン | 賃貸CF 月50万への距離、返済比率50%前後、次物件キープ資金 | `/realestate/buy-plan`、`/lifeplan?mode=re_purchase`、部長 |
| 2. 仕入れ（1次調査） | ポータル新着・業者メール | 「聞く」物件の第一問合せ | 戸建 500〜3500万・土地値100%超 / 一棟AP 1000〜3000万・土地値150%前後、耐震・ハザード | `/realestate/deals`、S1、S2 |
| 3. 判断（2次・3次調査） | 仲介から資料・返信 | **内見GO / 見送り** | 下の「内見GO」 | 内見ボード、S5、S3 |
| 4. 内見 | 内見GO | 買付へ進む / 見送り（保留は2週間まで） | 修繕概算込みで指値ラインに収まるか | 内見パネル（チェック9項目）、S4 |
| 5. 買付・融資 | 買付へ進む | 融資承認と売買契約 | 指値が通るか、承認条件で月CFプラス・返済比率50%前後 | 買付〜引渡しパネル、`/realestate/finance-pack`、S6・S7・部長 |
| 6. 取得・立ち上げ | 決済日確定 | 鍵受領、ライフライン・管理会社・保険、③-C と借入トラッカー登録 | 引渡しチェック完了 | S8、S9、S10 |
| 7. 運営 | 毎月の収支 | 空室・修繕・家賃の打ち手 | 年計画 vs YTD の差、空室日数 | `/realestate` ③-A、`/mq` |
| 8. 決算・税 | 年末・決算月 | 個人申告と法人決算、次年計画へ反映 | 前年比の差を説明できるか | `/tax`、`/mq`、家計B/S |

## 内見GO（フェーズ3の出口）

内見GO は「**机上で否定材料がない**」で出す。現地・地場仲介でしか分からないこと（室内・傾き・雨漏り・駐車可否の実物・成約家賃・空室期間）は「内見で確かめること」に回し、保留の理由にしない。

- **指値ライン（万円）** = 保守の想定家賃（万円/月）× 12 ÷ 0.15 − 修繕概算（万円）
- **内見GO**: 机上の否定材料がなく、指値ラインに届く見込みがある
- **見送り**: 再建築不可・ハザードの致命傷、または指値ラインに届く見込みがない
- **保留**: 机上で決まるはずの情報が欠けているときだけ。仲介への質問を付け、返事で再判定。期限2週間
- **ペース目安**: 机上GOの内見候補を常に3件、月2件内見

実装: `apps/trade-desk/lib/reViewingGate.ts`（指値ライン・机上判定・ペース）、S3 指示 `config/grok_supply_bot_grok_paste.md`（判定の基準）、同期 `scripts/jarvis_kurashift_obsidian_pick_sync.py`（`rent_conservative_man`・`viewing_checks`）。
