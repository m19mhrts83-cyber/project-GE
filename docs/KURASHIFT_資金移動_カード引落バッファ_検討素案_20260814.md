## 0. 課題（切実）

- Olive Infinite をメインにした結果、**月次カード引落が年2〜3回大きく膨らむ**（例: 2026-08 見込み **100万円超**）。
- これまで Marriott 本線時代も「各口座に引落分を残し、余りをメインへ寄せる」でしのいできたが、**手元キャッシュが潤沢ではない**。
- 一時しのぎの寄せ集めではなく、**ギャップ検知 → 無料レールで集約 → 不足時だけ調達ラダー**を、資金移動オペ（draft→承認→手順アシスト）に載せる。

### いまの流動性スナップ（2026-08-13・参考）

| 口座 | 残高 |
|---|---|
| 三井住友銀行 刈谷（Olive本丸候補） | 約68万 |
| 住信SBIネット銀行（合算っぽい2行） | 約53万＋約24万 |
| MUFG アパート／豊明ほか | 各〜数十万 |
| **流動性合計** | **約398万** |

→ 100万超の引落そのものは「家計全体の現金」では足りうるが、**引落口座（SMBC）に載っていない**ことが本質。固定費・物件バッファを食い潰さない寄せ方が必要。

## 1. 資金移動の手段（無料レール）

方針: **手数料0を優先**。有料振込は原則使わない。

| # | レール | 使いどころ | 注意 |
|---|---|---|---|
| A | **住信SBI ↔ 三井住友** の無料振込枠 | 月内の寄せの本線。給与余り・SBI側余剰 → Olive（SMBC） | 無料回数・時間帯を毎月確認。枠超過で有料化しない |
| B | **エアウォレット**（COIN+／MUFG系） | MUFG（豊明・アパート等）↔ 他行のハブ。チャージ・出金・送金が無料設計 | 登録口座・出金先が Olive/SMBC に届くか**初回だけ実機確認**。ことら対応拡大中（2026-07〜） |
| C | **ことら送金** | 10万円以下の個人間・対応アプリ間の無料即時 | **1件10万上限**のため、100万超は**分割**。Oliveアプリ／SBIアプリ／エアウォレット等の対応状況を都度確認 |

### 推奨フロー（寄せ）

```
① 各行に「当月の固定引落＋バッファ」だけ残す
② 余剰を無料レールで SMBC（Olive引落口座）へ
   SBI無料枠 → ことら分割 → エアウォレット（MUFG経由）の順で枠を消化
③ それでも SMBC 不足なら §2 調達ラダー
```

## 2. 現金不足時の調達（優先順位・推奨）

ユーザー案 (a)海外債利息 → (b)株式売却 → (c)契約者貸付 に対し、**IFA＋寝かせて＋金持ち父さん**で並べ替え。

| 順位 | 手段 | 判定 | 理由 |
|---|---|---|---|
| **0** | 銀行内の寄せ（§1） | 必須 | 資産を崩さない。まずはこれ |
| **1** | **(a) 海外債の「既入金の利金」**を送金 | 推奨 | あかつき本体は**売らない・増やさない**。口座に溜まった利金・余剰現金の移動は「現金管理」であり投資解約ではない |
| **2** | **(c) 契約者貸付（既存ソニー等）** | 条件付きブリッジ | 金利目安 **年2.5%**。**定額返済カレンダー**（月額・期間・原資）が書けるときOK＝株再建と同型の強制貯蓄。防衛・次物件・NISA9万の余りから払う。書けない／余枠が無いなら Bloomo。既存残高があるなら追加上限を計算 |
| **3** | **(b′) Bloomo（衛星）の一部売却** | 条件付き | 返済枠が給与に乗らない／宿題を早く閉じたいとき。再建は余り枠で任意 |
| **4** | **(b″) SBIインデックス（コア）売却** | 最終手段 | 『寝かせて』に反する。税・機会損失。**原則禁止**（本人が明示合意したときだけ） |
| **禁止に近い** | あかつき**元本**売却でカードを払う | 不可 | 方針「売らない」。利金のみ可 |

### 定額返済＝株式再建と同型か（2026-08-14）

**財務プロ判断: 条件付きでよい。** 毎月定額で負債を埋める感覚は正しい。差は「利息約2.5%」と「戻る先が保険CSV」。ライフプランの余り枠に月額を割り当てられるなら採用可。

### ユーザー案との差分（1行）

**(b) と (c) を入れ替え**、株式は「コア売却」ではなく「衛星→コア」に分解する。**(c) は定額カレンダー付きなら積極採用可**。

## 3. 持続可能な仕組み（アプリ）

### トリガー

| タイミング | 動作 |
|---|---|
| **財務お知らせ（Gmail）** | `scripts/jarvis_card_debit_watch.py` が Vpass「お支払い金額のお知らせ」等を取り込み → state / `sync_meta.card_debit_watch_summary` |
| 引落日の **T−14** | Infinite 本線: 金額≥50万 **または** SMBC不足>0 でホーム「いまやること」＋状況ウォッチ warn |
| 他カード | 金額≥30万のときだけアラート（未満は出さない） |
| ギャップ > 0 | `/money-ops` に **card_settlement_buffer**（プレフィル可。自動振込なし） |
| 年2〜3回の大型月 | 同じプレイブックを再利用（Infinite が第1号） |

**正**: 金額・引落日は **財務通知（Gmail）＋不足時は Vpass で確定**（`--set olive_infinite --amount … --due …`）。Zaim は事後突合のみ。カードHPスクレイプは Phase 2。
**年会費**は `card_annual_fee` のまま（本ウォッチと混ぜない）。

### オペ状態

`draft → consulting → approved → executing → done`  
承認＝「この寄せ／調達でよい」の合意。**銀行操作は手順アシスト＋手動**。
