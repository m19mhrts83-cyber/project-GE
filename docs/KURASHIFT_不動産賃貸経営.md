# KURASHIFT ③ 不動産賃貸経営

**法人＋個人を合算**して賃貸経営を扱う第3の柱。  
**サブレーンは4本に拡張**（ユーザー方針 2026-08-12 追記）。実装は段階的。本ドキュメントが設計正本。

---

## 位置づけ（3本柱）

| # | 分類 | 内容 | 主な画面 |
|---|---|---|---|
| ① | 資産運用 | 把握／提案・相談・実行 | ホーム・資産・テーマ・**家計B/S**（`/household-bs`） |
| ② | 計画・税 | ライフプラン更新／個人確定申告 | ライフプラン・ROI・個人申告 |
| **③** | **不動産賃貸経営** | **下記 ③-A〜③-D** | **不動産**（`/realestate`）・**MQ会計**（`/mq`） |

既存の **19不動産・δ・`/lifeplan?mode=re_purchase`・`/roi`** は②との接続点。③は**事業としての賃貸経営**に特化する。  
**合算デフォルト**は `/mq`（事業）と `/household-bs`（家計全体）で共通。家計B/Sは MQ の軽量B/Sに家計を足し込まない（画面分離）。月次スナップは MQ月次更新成功時に自動保存され、未保存でも live compose で表示できる。

## ③ 内のレーン（分離して設計・実装）

| レーン | 目的 | いつ使う | 画面（案） |
|---|---|---|---|
| **③-A 運用・計画進捗** | **今持っている資産**が、年間計画に対して**現在進行形でどうか**を見る。差分分析・補正 | 日常〜四半期。LP 年次更新とも接続 | `/realestate`（タブ: 運用） |
| **③-B 新規購入検討** | **これから買う物件**を長期プランと実行に分ける | プラン更新／候補が出たとき | `/realestate/buy-plan`（長期）＋ `/realestate/deals`（千三つ） |
| **③-C 保有物件マスタ** | **今所有している物件**の基本情報を一覧。ローン条件は**借入残高トラッカー**を正本として連携 | 資産把握・融資準備の土台 | `/realestate/properties` |
| **③-D 融資提出パック** | 融資時に銀行へ出す**書類一覧表**。必要事項を入力し、**融資向けに出力** | 新規融資・借換え・追加融資のたび | `/realestate/finance-pack` |

**混ぜない**: 運用ダッシュボード／購入案件／物件マスタ／融資パックは画面・データを分離。  
**つなぐ**: ③-B approved → 取得 → ③-C に物件追加 → ③-A 計画へ。③-D は ③-C の物件・ローン・法人情報を参照して自動埋め。

### 年収・号室・評価の置き場（2026-08-16）

| 見たいもの | 正 | 置かない |
|---|---|---|
| **買い物の良し悪し**（表面／実質／CF-ROI／CoC／**返済比率**） | **② `/roi`** | ③に評価表を複製しない |
| **号室・家賃・管理費・キャンペーン・住所・管理会社** | **③-C `/realestate/properties`**（保有マスタ） | ROI に号室表を置かない |
| **いまのCF・計画差・改修・空室の進み** | **③-A `/realestate`** | マスタに進捗バーを置かない |
| **ローン残高・月返済** | 借入残高トラッカー正本 → ③-C 投影 | ROI にローン明細を置かない |

**返済比率** = 年返済 ÷ 年収。目安 **50%前後**（MG会計・中津さん。会話では 50〜60% も言及）。購入時は満室年収、現況は入居中年収。③-A の DSCR（家賃÷返済）は余裕の見方で、複製しない。

**運用中の読み方**: アプリ [`/guide`](https://jarvis-trade-desk.vercel.app/guide)（構成ガイド・サイドバー「運用」）。KPI / Portfolio / Jobs / Focus / B-RATE はレーンではなく画面内見出し。

## ③-C 保有物件マスタ — 要件（2026-08-13 更新）

| 項目 | 方針 |
|---|---|
| **対象** | 法人＋個人の**現保有物件**（棟／戸建単位） |
| **基本情報** | 名称・所在地（**郵便番号**付き）・**鍵番号**（Notion 所有物件関係）・構造・築年・戸数・取得日・名義（個人／法人）・管理会社 等 |
| **ローン情報** | **借入残高トラッカー**で入力・更新。**KURASHIFT は二重入力しない** |
| **連携方針** | トラッカーを**ローン正本**とし、KURASHIFT は **読取投影**のみ（ジョブ案: `re_sync_loan_tracker`） |
| **URL** | https://loan-tracker-plum.vercel.app/ |
| **Google ログイン** | **estate**（`matsuno.estate@gmail.com`）— Drive に借入データを保存 |
| **既存資産** | `property_units`（号室・家賃・空室）、`config/property_info.yaml`（管理会社・鍵・名義）、`config/kurashift_re_property_master.yaml`（③-C 最小突合）、Numbers `19不動産` |

旧称「本田さんアプリ／本田連携待ち」はこのトラッカーを指す。すり合わせ待ち（名称・URL）は **解消**。残作業は Drive 保存形式の調査と sync 実装。

## ③-A 運用・計画進捗 — 要件

| 段階 | 内容 |
|---|---|
| **計画の立て方** | 不動産の支出・収入**実績**から年間計画を作成（Numbers `19不動産`／表1・表2 と同系） |
| **進捗確認** | 当年計画に対し、**今どこまで来ているか**（YTD 実績 vs YTD 計画） |
| **差分分析** | 科目別・物件別（可能なら）の**ギャップ**を可視化 |
| **補正** | 差分を見て**計画を修正**し、必要なら LP／Zaim 予算へ反映（承認付き） |

**合算**: 画面上部で **個人／法人／合算** を切替。デフォルトは **合算**。

## データモデル（案）

### エンティティ

| 値 | 意味 | 主なソース（案） |
|---|---|---|
| `personal` | 個人の賃貸収支 | Zaim 19.x／δ（既存 `jarvis_kurashift_lifeplan`） |
| `corporate` | 法人（リビングサポート松等） | MyKomon／税理士CSV／手入力（要すり合わせ） |
| `combined` | 表示用集計 | 上記の合算（DB 行ではなくビュー） |

### テーブル（Phase 2 以降で migration）

```sql
-- 年間計画（月次12行 or 科目×月）
kurashift_re_annual_plans (
  id, fiscal_year, entity, label,
  plan_json,          -- { months: [{month, income, expense, by_category}], totals }
  source,             -- numbers | manual | revised
  created_at, notes
)

-- 月次実績（取込 or 手修正）
kurashift_re_actuals (
  id, fiscal_year, month, entity,
  income_jpy, expense_jpy, cf_jpy,
  breakdown_json,     -- Zaim/MyKomon 科目内訳
  source, ingested_at
)

-- 新規物件検討（Phase 3）
kurashift_re_deals (
  id, title, status,  -- draft | reviewing | approved | dropped | acquired
  entity_planned,     -- personal | corporate | both
  summary_json,       -- ユーザー定義フィールドを後から拡張
  linked_theme_id,
  created_at, updated_at
)
```

既存 **`property_units` / `property_occupancy_events`**（空室・入居）は③の**稼働率・家賃収入の説明**に参照。  
既存 **`kurashift_plan_snapshots`** の `re19` メトリクスは②との橋渡し（③の合算には entity 次元を追加）。

## 法人データについて（要すり合わせ）

合算の**法人側**は次のいずれか（または併用）を Phase 2 前に決める:

1. **MyKomon** 月次試算表／賃貸科目エクスポート  
2. **税理士** メール添付（既存 `kurashift_tax_evidence` パターンの法人版）  
3. **手入力**（四半期1回など最小運用）

個人側は **Zaim 19.x** が既にパイプにあるため Phase 1 から可能。
