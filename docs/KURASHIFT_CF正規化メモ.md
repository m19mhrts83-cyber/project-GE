# KURASHIFT — CF（キャッシュフロー）正規化メモ

最終更新: 2026-08-13

## 目標

- **長期目標**: 賃貸からのキャッシュフロー **月 50万円**
- **KPI の正**: **個人＋法人の賃貸 CF 合算**（税引前の運用イメージ。確定申告の所得とは別）

## 画面での出し方

| 表示 | 定義 |
|---|---|
| **想定CF（満室）** | 保有物件の満室年収（レントロール）− いまの月返済。ノミナル。取得税・固都税・修繕は含めない |
| **実CF（定常）** | Zaim 19系の家賃 − ローン − 管理・毎月経費。**完成月**（当月20日未満なら前月まで）で割る |
| **家賃の差** | 想定家賃 − 実家賃。空室・キャンペーン賃料・管理会社差引後NET・入金ずれ |
| **特別支出** | 不動産取得税・固都税・修繕・年払い火災保険・広告・法人税 |
| **カバー率** | （定常月次 × 12）÷ 当年特別支出。1未満ならその年の一時費用を定常CFでは賄いきれていない |
| **会計の月次** | 特別込みの収入−支出÷月。マイナスでも一時費用の割り戻しであることが多い（ホーム③の旧「−15万」） |
| 目標（月） | 500,000 円 |
| ギャップ（想定） | 目標 − 想定満室CF |

正本スナップ（LP）は実績年優先（例: 2025）。`kurashift_plan_snapshots`。  
実装: `apps/trade-desk/lib/reSteadyCf.ts` · `/` ホーム③ · `/realestate`。

### 暦年カテゴリ年次 vs 月次トランザクション

KPI の定常／特別の分解は **`kurashift_finance_transactions` の subcategory** を使う。
`kurashift_finance_category_year` は 19F が一塊で、取得税もローンも混ざるため月次KPIには使わない。

### いまの差分注記（2026-08）

- **会計生の月次がマイナス**な主因は、不動産取得税・固都税・修繕などの特別支出を経過月で割っていること。定常（家賃−ローン−管理）はプラス側になる
- 満室想定（レントロール−返済）と実家賃の差は、空室だけでなくキャンペーン賃料・管理会社差引後NET・入金タイミングも含む
- 法人側の家賃・返済は合算 KPI に含める（2026-08-13 承認）
- subcategory でローン／経費／特別を分解（`19F` 一塊は使わない）
