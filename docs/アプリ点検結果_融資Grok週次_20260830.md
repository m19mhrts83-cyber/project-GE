## 是正バックログ（実務者向け）

優先度: P0=整合バグ／運用崩壊、P1=設計どおり動かす必須、P2=接続強化

### P0 — 材料の二重注入 ＋ 周期リセット ＋ 一覧（Q6 確定）

| 項目 | 内容 |
|---|---|
| **問題** | `pending` のまま再注入。グルコン未投稿月の材料が翌月にも残る。材料・未投稿下書きが一覧で見えない |
| **是正** | (1) `markGluconPosted` → `used` (2) **グルコン日翌日** pending 活動材料 → `cycle_closed` (3) **`/glucon/materials`** 新設（活動/成果タブ · 全 status · draft/ready 下書きも表示） |
| **設計正本** | `docs/Grok_グルコン材料_設計_20260830.md` |
| **受入** | 未投稿月でも一覧参照可。グルコン日後は注入されないが履歴は残る |

### P1 — 週次サマリーの Jarvis 側（Q1）

| 項目 | 内容 |
|---|---|
| **問題** | Grok は `10_inbox_from_grok/` に書く設計だが、`jarvis_bucho_inbox_poll.py` は **action 別処理なし**（未処理検知のみ）。`notion_tasks` は別スクリプト。`weekly_summary` は **孤児 MD** になりうる |
| **是正（推奨A）** | (1) poll で `action: weekly_summary` を認識し situation_watch / triage 相当に載せる (2) 見たあと archive 可 (3) 専用 apply は後回し可 |
| **受入** | 日曜夜に MD を置く → 翌朝ダッシュボードに「ホーク週次サマリー」が未処理として見える |

### P1 — 年会費・大型引落の実データ経路（Q3）

| 項目 | 内容 |
|---|---|
| **問題** | ホークは `@リソース経営部長` に常設確認するが、リソース paste に **年会費・大型引落の節がない**。正本は Mac `card_annual_fee.json` / `card_debit_watch` で **Grok は読めない** |
| **是正（推奨A）** | Jarvis: 週次前（日曜昼〜夕方）に秘密なし要約を `outbox_to_teams/resource/` へ。リソース paste に「週次は outbox の年会費・引落メモを先に読む」を追記。ホークはリソースから1行吸い上げ |
| **受入** | ホーク週次のアテンションに、実在する次回年会費日・引落注意が載る（推測だけにならない） |

### P1 — グルコン材料の取込タイミング

| 項目 | 内容 |
|---|---|
| **問題** | `jarvis_glucon_materials_from_drive.py` は **手動のみ**。launchd / 朝オープン / inbox poll に無い → inbox に置いても `/glucon` に出ないままになりやすい |
| **是正** | 最低: 朝オープンまたは inbox poll のついでに `--apply`。失敗しても本題は止めない |
| **受入** | Drive inbox に MD → 自動または日次1回以内に DB pending になる |

### P2 — lenders ↔ 買い進めパイプライン（Q4）
