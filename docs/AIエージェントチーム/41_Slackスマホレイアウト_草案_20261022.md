## 調査メモ（公開知見・目安）

数値は端末・フォントで揺れる。**ルール上の目安**として使う（厳密計測ではない）。

| 出典・論点 | 目安 |
|---|---|
| 日本語・スマホ1行（Keeperz 等） | 快適 **約20字**／Slack 実測系 **約21字** |
| PCで打つときの行長 | **34字以内**を目安（スマホで二重折り返しになりにくい） |
| 1画面に収まる量（sinlab・iPhone8相当） | **約350字**／**約15行**前後 |
| 通知プレビュー | **先頭1行だけ**が見えることが多い |
| メッセージ全体 | 本題は短く（疲労研究では **約100字**が読みやすい帯）。詳細はスレ／docs |
| 改行の取り方 | **意味の切れ目**で改行。文の途中で機械的に切らない（クライアントが再折り返しする） |
| 塊 | **1〜3行の塊**のあいだに **空行1つ** |
| 等幅・桁揃え | **禁止**（比例フォントで崩れる） |

## ルール本体（草案）

対象: `#report` / `#consult` / `#ops` / `#ai-hub`（および同型の Bot 転記）。  
本日分・夕方・仲介返信パック・S1・天気・ダイジェストも同じ。

### 1. 先頭1行（通知＝これだけ見える）

- **番号＋短い役割語**（またはツール名）。番号だけ／役割語だけは不可。
- その行だけで「誰の何の報告か」が分かる。
- 例: `【報告】天気お知らせ・朝` ／ `【相談】312 Todoist起票整理`

### 2. 要ボス・優先

- 先頭付近に **📌要ボス** 最大 **3**（無ければ `要ボス: なし`）。
- 優先リストは最大 **5件**。超過は「他N件→正本（Todoist等）」1行。

### 3. 行長・改行・空行

| ルール | 内容 |
|---|---|
| 1項目 | スマホ表示で **2行以内**（目安 **40字前後**／1行約20字） |
| 塊 | 1〜3行の塊の **あいだに空行1つ** |
| リスト | `•` / `・` / `-` / 番号付きの **項目のあいだも空行**（詰まって見えないのを防ぐ） |
| 意味改行 | 文の途中で切らない。長い説明は **別項目**か **スレッド**へ |
| 入れ子 | 箇条書きの入れ子・長い（）は使わない |
| 全体 | 目安 **15行／約350字**まで。超える分はスレまたはリンク |
| 変化なし | 変化なしは **1行**にまとめる |

**悪い例（詰まって折り返し地獄）:**

```
・今日: くもり一時雨 降水30% ・予定: 打合せ2件 ・乗る便: 名鉄・メモあり
次: Jarvisに依頼
担当メモ: Macで○○
```

**よい例:**

```
・今日: くもり一時雨

降水: 午前10%／午後40%／夕方20%／夜10%

・予定: 打合せ2件

・乗る便: 名鉄（詳細はスレ）

次: Jarvisに依頼

担当メモ: Macで○○を実行

橋渡し: 松野了承後に Jarvis へ一声
```

### 4. `#consult` 末尾（次の担当）

3行は必須。**各行のあいだは空行1つ**（`36_` 正本）。

```
次: Grokで続行 | Jarvisに依頼 | 人判断のみ

担当メモ: （1行）

橋渡し: 松野が了承したら、上記の担当へ一声
```

### 5. 種別ごとの追加

| 種別 | 追加ルール |
|---|---|
| **天気** | 項目（天気／予定／乗る便／明日／メモ）のあいだに空行。本日降水は **午前／午後／夕方／夜** の4帯（1値にまとめない） |
| **ダイジェスト（312/313/メール等）** | 案件（または `#1` `#2`）のあいだに空行。返信は **番号指定**（例: `起票して 1,3`／`閉じて 2`） |
| **進捗・レーン** | 停滞コードだけでなく **担当の中身**が分かる語（例: S2＝地場紹介依頼） |
| **障害・ops** | 長め可。それでもセクション間空行と「要ボス先頭」は維持 |

### 6. 出さない・やらない

- 等幅の表・桁揃え・先頭スペースでの字下げ合わせ
- docs の長い絶対パスを本文にべた書き（必要なら短い名前＋スレ）
- エラー全文の貼り付け
- **同日・同本文の連続投稿**（dedupe）
- 深いネストのツリー

### 7. 詳細の置き場

| 置く場所 | 例 |
|---|---|
| 本文 | 結論・要ボス・次アクション |
| 末尾「参考」またはスレッド | ID・msg番号・時刻・長いログ |
| docs / Todoist | 手順・設計・証跡リンク（コメントは短く） |

1. 先頭1行だけで通知として通じるか  
2. 要ボスは3つ以内か／なし明示か

4. 1項目が2行を超えていないか  
5. 表・長パス・入れ子が無いか  
6. 15行超ならスレ／リンクに分けたか
