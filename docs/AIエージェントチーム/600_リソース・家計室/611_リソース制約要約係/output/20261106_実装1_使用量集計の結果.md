## 3. Supabase の置き場（案・未実行）

既存スキーマを確認した結果: 台帳 DB（`20261104_comm_hub.sql`）は「1 件 = 1 行、`check` で値を縛る、`payload jsonb`、`created_at/updated_at` とトリガー、RLS 有効＋anon/authenticated から revoke（service_role のみ）」の型。Cursor は既存の `sync_meta`（key/value）に写している。

**当面**: スキーマ変更なしで既存 `sync_meta` の key `ai_usage_weekly` に写せる（`--push`）。週次 runner からは **まだ `--push` を付けていない**（松野さんの了承待ち）。

**案（承認後に migration を作る）**: 台帳 DB と同じ型で 1 テーブル。

```sql
create table if not exists public.ai_usage_weekly (
  id uuid primary key default gen_random_uuid(),
  tool text not null
    check (tool in ('claude_code','codex','cursor','gencode','chatgpt_mode')),
  period_start timestamptz not null,
  period_end timestamptz not null,
  source text not null check (source in ('local_log','manual')),
  weekly_pct numeric,            -- 最新の週次％（Codex はログ、他は手入力）
  weekly_pct_max numeric,        -- 窓内の最大
  five_hour_pct_max numeric,
  requests int,                  -- Claude=応答数、Codex=ターン数
  sessions int,
  tokens jsonb not null default '{}'::jsonb,
  limit_hits jsonb not null default '[]'::jsonb,
  level text check (level in ('ok','warn','attention','unknown')),
  payload jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (tool, period_end)
);
-- RLS 有効、anon/authenticated から revoke（comm_hub と同じ）。updated_at トリガーも同じ型
```

動きB（配車案）の履歴は次の弾で別テーブル（`ai_dispatch_log` 等）を案として出す。
