## 3. Supabase の置き場（2026-11-09 確認・新テーブルは作らない）

確認（2026-11-09、service_role で読み取りのみ）: 個人ダッシュボードのプロジェクト `idkdqneutpvkhxhpjtgc`（Pro）。公開テーブル 104 本の中に使用量用のテーブルは無い。似た用途の既存テーブルが2つある。

| 既存テーブル | 中身 | 使い方 |
|---|---|---|
| `metrics` | `metric, value, unit, entity, recorded_at(date), payload jsonb`。`(metric, entity, recorded_at)` で一意。家計・Vポイント等が既に載っている | 週次の数値を 1 指標 1 行で載せる（`entity`＝ツール） |
| `sync_meta` | key/value。Cursor ウォッチも同じ型 | key `ai_usage_weekly` に最新の全体 JSON |

**結論: 新テーブル `ai_usage_weekly` は作らない。既存 `metrics` に載せる**（スキーマ変更なし）。1 週あたり 5〜10 行で、Pro の容量には影響しない。動きB（配車案）の履歴を残す段で、型が合わなければその時に改めて案を出す。

`metrics` に載せる指標（`recorded_at` は集計日）:

| metric | entity | 単位 | 出所 |
|---|---|---|---|
| `ai_usage_weekly_pct` | claude_code / codex / cursor / gencode / chatgpt_mode | pct | Codex はログ、他は手入力（入っているものだけ） |
| `ai_usage_weekly_pct_max` | codex | pct | ログ（窓内の最大） |
| `ai_usage_output_tokens` | claude_code / codex | tokens | ログ（内訳は payload） |
| `ai_usage_requests` | claude_code（応答）/ codex（ターン） | 件 | ログ |
| `ai_usage_limit_hits` | claude_code | 回 | ログ（時刻・種類は payload） |
