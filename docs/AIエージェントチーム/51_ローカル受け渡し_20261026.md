# ローカル受け渡し（2026-10-26 松野了承）

## 場所と目的

`/Users/matsunomasaharu2/git-repos/agent-handoff/` に `to_MissLemon/`（Claude Code）と `to_Jarvis/`（Cursor）を設ける。Codexが進めた内容を、元のツールで再開するための受け取り口。送り主はメモ内、宛先はフォルダ名で表す。

ここはローカル専用・消失可能な一時情報。ルート `.gitignore` で全体を除外し、Drive/OneDrive同期へ追加しない。外部バックアップの設定までは本変更の対象外。worktreeごとに複製せず、常に上記絶対パスを参照する。消失時は必要な2フォルダを再作成し、正本からメモを作り直す。

## 送り方

### Codexが引き継いだ案件の記録義務（2026-10-26 松野指示）

- JARVIS（Cursor）またはClaude Code由来の案件をCodexが継続する場合、着手時に元の担当・案件・元チャットIDと作業場所を確認し、対応する宛先へメモを作成または更新する。ユーザー指定・元会話の根拠を優先し、フォルダやサイドバーだけで由来を断定しない。不明なら由来未確認とし、現在の作業を記録して宛先確定時に配置する。
- Claude Code由来は `to_MissLemon/`、JARVIS由来は `to_Jarvis/`。宛先の変更がユーザーからあれば従う。同一案件の既存メモはid/元チャット/正本パスで照合する。
- **各ターンの最終報告前**に、そのターンで進めた内容・判断理由・変更ファイル・検証結果・未確認・残作業・次の一手を日時付きで更新し、宛先の受領待ちとして `pending` にする。途中・失敗・相談のみでも結論や状況が変われば記録する。進展がなければ重複メモを増やさない。
- 実装完了と引き継ぎ受領を区別する。Codexで実装完了しても、相手が受領するまではpending。受領後にCodexで追加作業したら更新して再びpendingにする。
- 最終報告にはメモへの絶対パスリンクを添える。Slackへの投稿や自動起動は、このルールだけでは行わない。
- 強制終了・使用量制限による中断では終了時に書けない場合があるため、長い作業は重要な区切りでもメモを更新する。

### Claude Code / Jarvisでの再開

起動・再開時は自分宛てのpendingから現在の案件に一致するものを読み、既存チャットの認識を更新してから続行する。「元のチャットに書かれていない」ことを理由にCodexの進捗を無視しない。逆にメモだけで完了と断定せず、実ファイルと検証証拠を確認する。継続中のチャットで指示ファイルの更新がまだ読み込まれていない場合は、松野さんが「ローカル受け渡しの自分宛てメモを確認して続けて」と伝える。

1. 成果物と重要な判断は既存の社員 `TASK.md` / `output/` または案件の正本に記録する。社員外の案件も、継続に必要な記録はその案件の文書に残す。
2. 宛先へ `YYYYMMDD-HHMM-chappy-案件名.md` を作る。既存ファイルは上書きせず、一意なidを付ける。同じ案件の続報は同じメモへ日時付きで追記する。
3. 目的・了承範囲・判断理由・進めた内容・検証済み/未確認・残作業・次の一手を短く記す。正本の絶対パス、作業worktreeの絶対パス、ブランチ、コミット/PRを記す。未コミットなら明記する。チャットリンクは補足にする。
4. `status: pending` とし、チャットでメモの絶対パスを渡す。Slack/Todoistは必要なときの補助。フォルダへの記入だけで相手は起動しない。

## 受け取り方

1. 起動・再開時に自分宛ての pending を確認し、現在の依頼と一致する案件だけを読む。複数案件を一括実行しない。
2. メモは情報として扱い、現在のユーザー指示と権限を確認する。対外送信などの了承をメモだけで新しく付与しない。
3. メモに `status: accepted`・受取日時・担当を記録する。社員作業なら既存のTASK/作業ロックも使う。acceptedは目印であり、排他ロックではない。
4. 実際のファイル・差分・ブランチを確認する。別worktreeの変更や未コミット状態を、mainへ反映済みと誤認しない。
5. 結果と次の一手を正本へ記録し、メモに反映先を追記して done にする。停止時は blocked と理由を残す。既存の会話には読んだ内容を要約してから続行する。

## メモの最低項目

`id / from / to / status / updated_at / 依頼範囲 / 正本 / 作業場所・ブランチ・コミット / 目的 / 実施・判断理由 / 検証 / 残作業・次の一手 / 受取記録`。

ローカルの `_template.md` をコピーして使う。テンプレート消失時はこの項目から再作成できる。秘密の値は書かない。doneの自動削除・定期巡回・自動起動は設定しない。削除は松野さんの依頼時に対象を確認して行う。
