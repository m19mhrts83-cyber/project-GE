# 314 改善台帳（判断ログ → 改善 → 効果）

314 が週次レビューで毎回読んで更新する。`scripts/jarvis_owner_decisions_weekly.py` がこの表を読み、
状態が「実装済」「効果測定中」の行について **指標の今週の値** を改善前と並べる。

## 書き方

- **ID**: `IMP-001` から順番
- **状態**: `提案` →（松野さん承認）→ `承認` →（Jarvis／Miss Lemon が実装・テスト）→ `実装済` →（翌週以降に数字を見る）→ `効果測定中` → `効果あり`／`効果なし`（なしなら原因と再改善案を新しい ID で）／`見送り`
- **社員**: 週次まとめの社員キー（`312L`＝Loopware 312、`313L`＝Loopware 313、`312`・`313`＝Slack ボタン経由、`111+211`・`116`・`112`・`vendor`・`S9`）
- **指標**: `件数`・`承認率`・`修正率`・`見送り率` のどれか1つ
- **改善前**: 提案した週の値（例 `70%`）
- **根拠ID**: 週次まとめの「根拠 ID」をそのまま（判断ログ ID・Todoist ID）
- **分類**: `コード条件分岐`／`プロンプト`／`運用ルール`／`松野判断が必要`
- 提案は1週に **最大3件**。同じ理由が2件以上あるものだけ（1件は一般化しない）
- 既に Todoist／PR／別スレッドで扱っているものは足さない（二重起票・二重実装を避ける）。重なりを見つけたら「改善対象」にそのリンクを書いて `見送り`
