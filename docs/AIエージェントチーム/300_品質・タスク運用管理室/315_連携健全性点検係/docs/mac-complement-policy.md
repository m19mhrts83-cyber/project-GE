# Mac補完の方針（確定 2026-10-11 改定）

## 結論

| 項目 | 正 |
|---|---|
| 本線 | 日曜 **21:00** JST / GHA `--cloud` → `#ops`（検知） |
| Mac補完 | 日曜 **21:45** JST / launchd `--remediate-once` → `#ops`（1回トライ＋結果） |
| パートナー確認 | **復旧の必須経路ではない**（あってもよい） |

旧「パートナー確認ついで／第2定時なし」は、意図（自律で1回トライ）に合わせて **21:45 launchd** に置き換えた。

## なぜこの形か

パートナー確認も自動化が進むと「ついで」だけでは復旧が回らない。  
GHAだけでは Mac専用の復旧ができない。だから **GHA検知の45分後に Mac が1回トライ**する。

## アウトプット

| 何か | 行き先 |
|---|---|
| 315公式（GHA・Macとも） | Slack **`#ops`** |
| 1回トライ後も未解決 | `#ops` ＋ **`#consult`** |
| パートナー確認チャットのヘルス行 | 315公式ではない |

## 停止

- `JARVIS_OPS_HEALTH_315_DISABLE=1`（Mac launchd）
- GHA workflow 無効化

## やらないこと

- トークン再発行・QRの無人完了待ち
- WeStudy の自動再実行
- 構造限界を「直した」ことにする
