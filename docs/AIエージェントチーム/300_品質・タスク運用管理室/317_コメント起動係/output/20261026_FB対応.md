## 調査結果

- 投稿元: `apps/jarvis-dashboard/app/api/slack/consult-action/route.ts` の物件カード「問合せ送信 Yes」ボタン処理（`applyGate`、`lib/propertyGateAction.ts`）。
- 10/25 07:19 に Yes を押した時点で、Jarvis の Supabase プロジェクトが **無料枠の通信量（egress）超過で一時停止**しており、案件の読み込みに失敗。Supabase の英語エラー文がそのままカードに出ていた。
- **問合せは送られていない**（ジョブ作成前に失敗）。
- 2026-10-26 時点で Supabase は読み取り可能（REST 200）に戻っている。同じ案件はもう一度 Yes を押せば受け付ける。
- egress 超過そのものは 315（Codex, 10/25）が検出済みで Todoist `6hqg5j75rjx8RWG6` に起票済み（課金判断はオーナー）。

## 直したこと

- `lib/propertyGateAction.ts` に `toJapaneseDbError()` を追加。案件読み込み・ジョブ作成の失敗時に、
  - egress 超過 → 「Supabase の無料枠（通信量）を使い切り、一時停止中でした。問合せは送っていません。…」
  - 接続失敗 → 「データベースにつながりませんでした（問合せは送っていません）…」
  - その他 → 「データベースのエラーです（問合せは送っていません）」＋原文の先頭
- 「deal not found」も「対象の案件が見つかりません」に。
- 確認: `tsc --noEmit` 通過、変換関数を手元で実行して文言確認。

## 提案

- egress 超過が再発しうる。`jarvis_kurashift_openchat_sync.py` は抑制済みだが、他の大きな読み出し（embedding 列の select 等）の点検を 315 の次回点検に入れるとよい。
