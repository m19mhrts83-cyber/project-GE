## 3. アーキテクチャ（本線）

```
#consult ダイジェスト（起票してよければ番号で返信）
        ↑ 人「2」「起票して 1,3」「閉じて 2」
        │
   GAS poll（5分おき・admin 実行）
        ├─ Slack conversations.history / replies
        ├─ 番号パース（LLMなし）
        ├─ Todoist create /（後段）close
        └─ スレに ✅／❌（【FRIDAY】コメント方針は既存）
```

### Workspace 無料枠の目安（本線だけ）

5分おき × 1日 ≈ **288 実行**。1回あたり Slack 数回＋Todoist 数回の UrlFetch でも、Workspace の UrlFetch 日次上限（10万）・トリガー合計時間（6時間）に対して余裕。

### Claude を足す場合（任意・非本線）

```
GAS poll → 番号が取れない／曖昧な返信だけ
        → UrlFetch → Claude Messages API
        → 構造化JSON（nums / skip / need_human）
        → 確信度低なら #consult に「要人」だけ返す
```

- キーは Script Properties `CLAUDE_API_KEY`（`.env.jarvis_private` から転記。チャット禁止）
- **毎回 Claude はしない**（コストと遅延）
- Dify はフロー設計の試作に使ってよいが、本番スケジューラは GAS に寄せる（GHA 不可・PC不要）

## 4. 適用手順（admin・ローカル Jarvis）

Cloud Agent では **script.google.com の編集・OAuth・`.env.jarvis_private` 読取ができない**ため、**Mac／ローカル Jarvis** が実施する。

1. ブラウザ: **使用アカウント admin** で [script.google.com](https://script.google.com) を開く  
2. 既存プロジェクトを開く（上記 ID）／無題なら名前を `312_Slack_Todoist_ingest` に  
3. PR #118 の `scripts/gas_todoist_312_slack_ingest.gs` を `Code.gs` に貼る（doc 内の古いサンプルより **ファイル正本**）  
4. スクリプトプロパティ（値は jarvis_private から。チャットに出さない）:

| キー | 内容 |
|---|---|
| `SLACK_TOKEN` | Bot `xoxb-…`（history 済み） |
| `TODOIST_TOKEN` | Jarvis 分身トークン |
| `CHANNEL_ID` | `C0C7R0UF3MM`（#consult） |
| `STATE` | `{}` |

5. 関数 `poll` を実行 → **admin で** OAuth 承認  
6. トリガー: 時間主導・**5分おき**・`poll`  
7. テスト: `#consult` に存在しない番号 → 「番号が見つかりません」がスレに来れば OK  
8. 312 実運用確認後、313（`閉じて N` → close＋`【FRIDAY】タスク完了したよ`。**確認のみ自動 close はしない**）を同プロジェクトに追加  

ロールバック: トリガー削除。プロパティからトークン削除。
