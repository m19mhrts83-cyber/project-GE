# Jarvis／Cursor 上限時 — 物件進行ゲートの次善策

- 確定: 2026-10-12
- 対象: Grok調査 → 問合せ進行（[`23_物件進行ゲート`](23_物件進行ゲート_Grok調査_20261012.md)）
- 目的: **AI 会話が止まっても、プログラムで進むところまで進み、最後だけ人が Yes/No**

## 原則

| 層 | 誰が動く | Jarvis 上限でも？ |
|---|---|---|
| **プログラム本線** | launchd／朝バンドル／CLI | **動く**（Cursor 不要） |
| **人ゲート** | 松野が Slack Yes/No | **動く**（リンク or CLI） |
| **AI 会話** | Jarvis／Cloud Agent | 止まる → あとで振り返りだけ |

新規社員は増やさない。114＝振分プログラム、511＝送信プログラム、松野＝Bだけ。

## 自動で回るもの（Cursor 不要）

1. **Grok S1**（Bot）が `[Grok調査]` を estate へ送る  
2. **取込** `property_mail_match --grok-only`（朝バンドル／昼 11:00 launchd）  
3. **114 振分＋Slack** `jarvis_property_gate_degraded.py`  
   - 朝バンドル（取込直後・soft-fail）  
   - 昼 11:00 noon runner 末尾  
   - 専用 launchd **11:15**（取りこぼし）  
4. **Yes 後の送信** `kurashift_jobs` → Mac **job worker**（`re_deal_inquiry_send`）

無効化: `JARVIS_PROPERTY_GATE_DISABLE=1`

## 松野だけがやること（上限時の最短）

1. Slack `#consult` の【物件進行ゲート】Bカードを開く  
2. **Yes** または **No** リンクをタップ  
   -（未配線・トークン未デプロイなら CLI）  
3. To 未解決で失敗したらカード／スレの失敗1行を見て deals で To を直すか見送り  

```bash
cd ~/git-repos && set -a && source .env.jarvis_private && set +a
# いま手動でゲートを回す（上限時の一発）
~/selenium_env/venv/bin/python scripts/jarvis_property_gate_degraded.py
# Yes / No
~/selenium_env/venv/bin/python scripts/jarvis_property_gate_511.py --deal-id UUID --yes
~/selenium_env/venv/bin/python scripts/jarvis_property_gate_511.py --deal-id UUID --no
# worker が眠っていたら
launchctl kickstart -k "gui/$(id -u)/com.matsunoma.jarvis.kurashift-job-worker"
```
