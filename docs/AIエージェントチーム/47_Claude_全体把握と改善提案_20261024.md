## 4. 提案

### AI 使用量を抑える

1. **「いまの正」1 枚を作り、入口をそこだけにする**: 各テーマ（Slack 書式・枠切れ・定期実行など）の現行ルールを 1 ページに集約し、古い日付 MD は先頭に「→ 現行は ○○」を入れて読まずに済むようにする（G）。
2. **画像 PDF の横に元 MD を置く**: `materials_catalog.json` に `source_md` を持たせ、AI は MD を読む（H）。
3. **文字起こしは AI チャットでなく `jarvis_transcribe_m4a.py` を launchd で**: 録音フォルダを見張って自動で md 化（D）。
4. **「聞く」は軽いモデルから**: Cloud Agent 前に Gemini Flash 等で答え、足りないときだけ Cloud（現状は Cloud 既定）。
5. **定期 AI は週1レビュー 1 本を維持**、日次は増やさない。

### 品質を上げる

1. **PR 時 CI（AI 不要）**: `apps/**` 変更時に `npm ci && npm run build`、trade-desk は `npm test`、`scripts/tests` は pytest（E・F）。
2. **対外送信経路のテストを優先追加**: 問合せ送信（511・inquiry failover）・メール要対応（116）・Todoist 起票（312）。二重送信・二重起票の再発防止。
3. **Drive 同期の衝突検知**: `jarvis_agent_team_drive_sync.py` の後に ` [0-9]+.md` を探して `#ops` へ（C）。
4. **時刻精度が要るジョブ**は pg_cron→workflow_dispatch か launchd 本線（[`46_`](46_週次レビュー_20261023.md) の残課題どおり）。

### 安全（先にやる価値が高い）

1. Obsidian の `99_token,api key` を Drive ミラー対象から外す（中身は `.env.jarvis_private` へ寄せる）（A）。
2. Drive の `git-repos` ミラーから `.env.*` を除外（B）。
