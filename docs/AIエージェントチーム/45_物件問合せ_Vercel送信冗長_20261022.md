# 物件問合せ — Vercel 送信冗長（案 C）

- 確定: 2026-10-22（PR [#127](https://github.com/m19mhrts83-cyber/project-GE/pull/127)）
- 関連計画: 312 GAS 見送り → ボタン本線。物件 Yes 後の Mac スリープ耐性

## 結論

| 層 | 正 |
|---|---|
| **本線** | Mac `kurashift-job-worker`（`re_deal_inquiry_send`）＋送信前 **311 フル** |
| **冗長** | Vercel `GET/POST /api/inquiry-send-failover`（AI なし・定型＋Gmail） |
| **起動** | GHA `.github/workflows/inquiry-send-failover.yml`（15分刻み ping・毎正時回避。Hobby で Vercel Cron 不可のため。GHA は混雑で間引かれ実測 約4〜5時間おき＝ベストエフォート） |
| **停止** | `INQUIRY_VERCEL_FAILOVER=0` |

Mac が起きていれば failover は noop／claim 0。`queued` が約5分超のときだけ CAS claim → 送信。

## 設計ゲート（4点）

| # | 内容 |
|---|---|
| 入口 | Slack Yes → `applyGate` → `kurashift_jobs` `queued` |
| 確認 | ボタン了承済み。failover は再確認しない（人了承は Yes 時点） |
| 履歴 | job `done`／`failed` ＋ Slack 結果スレ。Mac 本線は `5.やり取り` 追記 |
| 停止 | `INQUIRY_VERCEL_FAILOVER=0`／token 無効化／GHA disable |

## 311

- Mac: フルゲート（`kurashift_inquiry`）
- Vercel: **lite**（self／運営宛ブロックのみ）。誤送リスクは claim＋`inquiry_status` で抑止

## やらないこと

- Cloud Agent に送信させる（AI 従量）
- GAS から対外送信
- failover を本線にして Mac を捨てる
