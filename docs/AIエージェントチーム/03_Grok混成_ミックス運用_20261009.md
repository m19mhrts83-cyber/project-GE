# Grok混成・ミックス運用（正本）

**更新**: 2026-10-10（対応表リンク追加）  
**室**: [`400_ミックス・取捨判断室`](400_ミックス・取捨判断室/)（411–415）

**誰が誰と同系統か（印）**: [`16_GrokBot対応_ミックスアップ識別_20261010.md`](16_GrokBot対応_ミックスアップ識別_20261010.md)

Grok Bot 系統と AIエージェントチームを**並べて比較し、採用／却下／差分フィードバック**する運用の正。  
指揮は **Jarvis（最上）**。枠切れ時は **813 代行指揮**へ。実行候補は Claude Code / Codex / GenCode（Friday）の3つ（Jarvis は俯瞰のみ）。  
**リソース**: **611** が AI使用状況とレビュー結果から社員の **頻度を減らす／増やす**案を出し、813とセットで枠＋頻度をコントロールする（本番変更は人確認後）。  
社員側の印: **〔Grok:S1〕**＝同系統の Mac 側／**〔ミックスレーン〕**＝比較レーン／印なし＝Grok同型なし。

## 1. 二系統の役割

| 系統 | 強み | 置き場 | やらないこと |
|---|---|---|---|
| **Grok Bot** | 判断・文案・ルーティン整理・チャンネル対話 | admin Drive `【with Grok bot】`（inbox／outbox） | Mac実行・秘密・対外送信の最終実行 |
| **AIエージェントチーム** | いけとも型・1社員1フォルダ・トリガー自律・Slack報告 | `docs/AIエージェントチーム/` | Grok チャンネルの代替にはしない |

フォーク方針: `config/grok_jarvisbox_fork_policy.md` · `jarvis-grok-jarvisbox-fork.mdc`

```text
松野
  └─ Jarvis（Cursor・俯瞰・オーナー確認・対外了承）
       ├─ 通常: GenCode / （将来）Claude Code / Codex に社員割当
       └─ 枠切れ・代行: 813_代行指揮・枠切替係 → 次候補へ
```

| 役割 | ID／誰 | 報告 |
|---|---|---|
| 最上指揮 | Jarvis | Todoist `[Jarvis]`・必要なら `#consult` |
| 代行指揮 | **813** | `#ops`（切替理由）＋ `#consult`（要人） |

**やらない**: 社員が勝手に他系統の正本を上書きする／Grok にトークンを渡す／了承前の対外送信。

## 3. 400室の流れ（1サイクル）

| 順 | 社員 | 入力 | 出力 |
|---|---|---|---|
| 1 | **411** Grok材料取込係 | Drive `10_inbox_from_grok/`・チャンネル要約 | 取り込みメモ（重複除外） |
| 2 | **412** 両系統比較係 | 411＋エージェント側成果 | 差分表（一致／食い違い／片方のみ） |
| 3 | **413** 取捨判断ドラフト係 | 412 | 採用／却下／保留案（理由1行） |
| 4 | **414** フィードバック返送係 | 413で「Grokへ返す」 | outbox MD（`jarvis_bucho_outbox_write`） |
| 5 | **415** 二重起票・競合監視係 | Todoist／inbox | 二重・競合フラグ → `#ops` or コメント |

人確認が要る案だけ `#consult`。業務完了は `#report`（Slack 準備後）。

## 4. 採用の判定（短いものさし）

| 判定 | 条件 | 次 |
|---|---|---|
| **採用（エージェント）** | トリガー・権限・報告が揃い、再現できる | 社員 `CLAUDE.md` §7＋`flow.md` に残す |
| **採用（Grok）** | 文案・方針の質が上／対話向き | Instructions／チャンネル運用へ。実行は Jarvis |
| **却下** | 重複・秘密リスク・正本と矛盾 | 理由を415 or 413ログに1行 |
| **保留** | 情報が足りない | `#consult` または Todoist オーナー確認 |
