対象: [物件と連絡の見守り隊](https://agent-team-builder-teal.vercel.app/s/eHKHNixTpIF4G5WN)（現行）／旧 `B8cQ9Q5XHtfrl2kF`  
ローカル正本: `docs/AIエージェントチーム/`（3桁フォルダ＋`agents_registry.yaml`）

## Jarvis の理解（要約）

あなたの実運用はすでに次のパイプラインになっている。ビルダーはその**図解版**としてかなり当たっている。

```
取込（Gmail/LINE/Chatwork）
  → 要確認要約（パートナー確認）
  → 下書き（送信前確認）
  → Todoist（起票／オーナー確認／完了）
  → 健全性（WeStudy/GHA/オプチャ）
並行: KURASHIFT買い進め・修繕・財務集計
```

| 部門 | 役割の読み |
|---|---|
| 連絡・物件動向把握室 | 入口と状態把握（連絡・LINE・買い進め・修繕） |
| 返信・案内文面制作室 | 人が送る前の文面作成 |
| 品質・タスク運用管理室 | 検収・タスク正本・完了二段・取込点検・数字 |

## 評価（良いところ）

- 実在の導線（yoritoori／Todoist二段／outbound確認／KURASHIFT）と噛み合っている
- 「送信は人」「完了はオーナー確認」など禁則がミッション文に出ている
- 1体目候補（送信前品質／取込点検）が品質室にあり、Day2の「1体作りきる」に使いやすい
- 部門3つは多すぎず、後から統合しやすい

## ブラッシュアップが必要なところ

1. **チーム名が弱い**（「見守り隊」がゆるい。司令・オペ・ハブ系へ）
2. **タスクが抽象**（スクリプト名・合図・成果物パスが無い → Flowforge／CLAUDEに落ちない）
3. **名称ゆれ**: ビルダー「週次取込点検係」↔ ローカル「連携健全性点検係（315）」
4. **データアナリストが広い**（Zaim／finance_metrics／ダッシュボードに範囲を絞る）
5. **200番台が1体だけ**（当面OK。将来「対外送信オペ」に統合するなら部門名を先に整える）
6. **タグ**: `事務・アシスタント`＋`不動産・建設`は妥当。チーム名変更後も維持で可
7. **tomorrowAgentName** が「パートナー連絡整理係」→ 1体目実装中は「送信前品質係」か「連携健全性点検係」の方が学習効果が高い
