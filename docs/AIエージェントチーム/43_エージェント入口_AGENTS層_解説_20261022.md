# エージェント入口 — root AGENTS（1番）と ~/.codex（2番）の違い

Codex／他ツールへのルール引き継ぎ相談（2026-10-22）の解説正本。

## たとえ

リポは大きなオフィスビル。

| 案 | たとえ | 何が起きるか |
|---|---|---|
| **1番 root `AGENTS.md`** | **ビル入口の案内板** | Codex がリポのどこで起動しても、最初にこの板を読む（Git root の `AGENTS.md`） |
| **2番 `~/.codex/AGENTS.md`** | **自分の名札・家訓** | どのリポでも、Codex 起動時に先にこれを読む（マシン個人） |

## 1番（root AGENTS）をもう少しだけ

いまのルート `AGENTS.md` は、主に **Cloud Agent 向けのアプリ起動手順**（kamiooya-qa / dashboard の port 等）が入っている。  
**AIチームの運用ルール**（Slack・Todoist・秘密・社員 CLAUDE）への案内は、ほぼ書いていない。

だから Codex がリポ root で「何かやって」と頼まれると:

1. Cloud 用のアプリ説明は読む  
2. でも **チームの `CLAUDE.md` へ行け、とは書いていない**  
3. 結果、Slack／Todoist の家ルールを知らないまま動きやすい  

**1番でやること**は、ルート `AGENTS.md` の先頭か末尾に、例えば次の **数行だけ**足すこと（アプリ手順は消さない）:

```markdown
## AIエージェントチーム（運用）

チーム作業・Slack・Todoist・社員フォルダに触るときは、先に読め:
- docs/AIエージェントチーム/AGENTS.md → 正本 CLAUDE.md
- 社員単位なら docs/AIエージェントチーム/…/NNN_…/AGENTS.md → CLAUDE.md
秘密はチャットに出さない。起点は Jarvis。
```

これで「フォルダのパスを口頭で言う」より、**Codex が自動で入口を踏む**確率が上がる。  
（社員フォルダの中で起動したときは、その階の `AGENTS.md` も追加で読まれる。）

## 2番（賛成済み）との役割分担

| | 1番 root | 2番 ~/.codex |
|---|---|---|
| 効く範囲 | **このリポ** | **この Mac／環境の全リポ** |
| Git 管理 | ○（チームで共有） | ×（個人。example だけリポに置く） |
| 向いている内容 | 「チーム作業はあのフォルダへ」 | 「秘密禁止・了承ゲート・起点 Jarvis」 |
| 草案ファイル | （必要なら root に追記） | `config/codex_home_AGENTS.example.md` |

**推奨**: 2番を先に置く（賛成どおり）。1番は「root で動かしたとき迷子にならない保険」として、短文を後から足せばよい。
