## 1. 合意した切り分け

| 層 | 何が動くか | Cursor／GenCode クレジット？ |
|---|---|---|
| **GHA 定例**（約22本） | Python／API／Playwright | **ほぼ No** |
| **launchd 定例** | 同上（Mac 専用） | **ほぼ No** |
| **例外: Ops Fail autofix** | triage 末尾 `--autofix` | **Fail（attention/warn）のときだけ** Cloud Agent |
| **cursor-revise-worker** | ダッシュボード見直し／聞くのキュー | **キューがあるときだけ** |
| **Cursor 対話 Jarvis** | このチャット等 | **Yes（本丸）** |
| **GenCode（FRIDAY／Mesh）** | 人手・代行の Mac CLI | **Yes（Genspark）** ※GHA からは起動しない |

**やらないこと**: 動いている GHA 定例を GenCode 定期に載せ替えない（クレジット依存と信頼性が悪化する）。

**節約の本丸**: 対話・Cloud Agent・Fail 時 autofix。定型の本番は GHA／launchd のまま。

## 4. Ops Fail autofix ゲート（検討結果）

| 方針 | 内容 |
|---|---|
| **現状（推奨）** | triage の `--autofix` **維持**。Fail が稀で、直近は Cloud 未起動 |
| **抑制したいとき** | Secrets／env に `JARVIS_OPS_FAIL_AUTOFIX_DISABLE=1`（スクリプトが `--autofix` を無視） |
| **完全オフ** | workflow から `--autofix` を外し `--push` のみ（了承後） |

コード: `jarvis_ops_fail_watch.py` が上記 env を尊重。workflow は既定どおり `--autofix` のまま（挙動変更なし）。
