# ニュース配信 — Banto Webhook＋興味評価（2026-11-08）

## 方針

ChatGPTで運用していた本人向けニュース4本を **番頭さん（Banto／Muse）** へ移管する。  
**投げる権限は Banto**（`#report` Incoming Webhook）。興味の回収・DB・要約は **Jarvis**。

いけともAIニュースは対象外。

| feed_id | 名前 | 目安時刻 |
|---|---|---|
| `cursor_friday` | Friday Cursor Automation Brief | 金曜 23:08ごろ |
| `ai_weekly` | AI源流・未来動向ウィークリー | 日曜 19:00 |
| `space_defense_daily` | 宇宙・防衛・AIデイリー | 毎日 22:30 |
| `defense_mgr` | 防衛宇宙・製造管理職ブリーフ | 毎日 22:30 |

## 設計ゲート4点

| 柱 | 正 |
|---|---|
| **入口** | Banto が原稿を作り、Muse から `#report` Webhook へ項目別 POST |
| **確認** | 松野が 👍／👎（任意でスレコメント）。ChatGPT停止は松野明示承認のみ |
| **履歴** | Supabase `jarvis-dashboard` の `news_*`。興味要約 → Drive JarvisBox outbox ＋ `.jarvis_state/news_interest_summary.md` |
| **停止** | `.jarvis_state/news_digest.json` の `disabled` または `JARVIS_NEWS_DIGEST_DISABLE=1` |

## 秘密の扱い

- `#report` 用 Webhook URL（`.env.jarvis_private` の `SLACK_WEBHOOK_AI_TEAM_REPORT` と同値）を **Muse の私有設定**へ松野が入れる。
- URL を Slack／チャット／公開 MD に書かない。
- Supabase `service_role` は Muse に渡さない。

## 投稿フォーマット（Banto必須）

項目ごとに1投稿（Webhookはスレ起点作成不可）:

```
【ニュース】④防衛宇宙・製造管理職｜YYYY-MM-DD
（本文）

👍興味 / 👎イマイチ
meta: feed=defense_mgr item=YYYYMMDD-01
```

表示名例: `ニュース ④防衛宇宙`

## Jarvis コマンド

```bash
cd ~/git-repos && set -a && source .env.jarvis_private && set +a
# 投稿メタを DB 登録
~/selenium_env/venv/bin/python scripts/jarvis_news_posts_sync.py --apply
# 👍👎・スレ → 興味ログ＋要約
~/selenium_env/venv/bin/python scripts/jarvis_news_interest_poll.py --apply
```

DDL: `apps/jarvis-dashboard/supabase/migrations/20261108_news_digest_interest.sql`
