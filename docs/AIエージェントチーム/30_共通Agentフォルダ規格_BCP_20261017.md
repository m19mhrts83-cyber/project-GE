## 結論

最初に足すのは新しいAI社員ではなく、**どの実行ツールでも同じ仕事を再開できる共通フォルダ規格**。  
既存の `_template/`（CLAUDE.md／AGENTS.md／README／flow／logs）を土台に、**依頼・入出力・検証**を明示する。

枠切れ時の人向け1枚: [`35_枠切れBCP_1枚_20261017.md`](35_枠切れBCP_1枚_20261017.md)（定例 GHA は枠非依存）。

## 位置づけ（既存との関係）

| 既存 | 今回の追加 |
|---|---|
| 1フォルダ＝1社員（いけとも型） | 維持 |
| `CLAUDE.md`＝正本指示、`AGENTS.md`＝互換入口 | 維持 |
| Drive `★AIエージェントチーム/` に data／outbox／logs | 維持（容量大はDrive） |
| Slack `#report`／`#consult`／`#ops` | 維持（報告は既設） |
| Cursor上限時の物件ゲート（[`24_`](24_Jarvis上限時_物件進行ゲート_次善策_20261012.md)） | プログラム本線の先例 |
| **TASK.md / input / output / tests / config** | **本規格で必須化（新規・磨き時）** |

完全に同じ品質になる保証はない。共通規格＋テストで比較し、差分をログに残す。

## 標準構成（Git 社員フォルダ）

```
NNN_名前/
  README.md          # 一目
  CLAUDE.md          # 正本指示（役割・合図・権限・報告）
  AGENTS.md          # 互換入口（日付同期のみ）
  TASK.md            # 今回の依頼・完了条件・実行ID（作業のたびに更新）
  flow.md            # 作業フロー初回叩き台（必須・空禁止）→ 後で FlowForge URL
  config/            # 項目定義・閾値・YAML断片（秘密の値は置かない）
  input/             # 入力資料の置き場（または外部正本へのパスメモ）
  output/            # 成果物（小容量）／大きいものはDriveパスを記す
  scripts/           # この社員専用の薄いラッパ（本線コードは ~/git-repos/scripts 可）
  logs/              # 実行履歴・エラー・比較メモ
  tests/             # 完了条件のチェックリスト／fixture
  .env.example
  00_🔵設計中.md 等   # status マーカー（syncで生成）
```

### TASK.md の最低項目

```markdown
# TASK

| 項目 | 値 |
|---|---|
| task_id | Todoist id または run_id |
| agent_id | 例: 114 |
| executor | cursor / claude_code / gencode / launchd / … |
| status | queued / running / done / failed / blocked |
| started_at | ISO8601 |
| finished_at | |

## 依頼
（何をするか・入力はどこか）

## 完了条件
- [ ] …
- [ ] tests/ のチェックを通す
- [ ] Slack 報告（必要なとき）

## 成果物
- output/… または外部パス
```

## BCP（実行ツールが変わっても続く）

| 状況 | やることを変えない | 変えてよい |
|---|---|---|
| Cursor 利用可 | 母艦として実行 | — |
| Cursor 制限・障害 | 同じ `TASK.md`＋`input/` を Claude Code／GenCode で開く | ツール固有のショートカット |
| 会話AI不要 | launchd／GHA／CLI 本線（[`24_`](24_Jarvis上限時_物件進行ゲート_次善策_20261012.md) 型） | 人が Yes/No だけ |

禁止に近いこと:

- チャットだけで完了条件を変え、`TASK.md` を残さない
- ツールごとに別フォルダへ成果物を散らす
- 秘密を `config/` や MD に書く
