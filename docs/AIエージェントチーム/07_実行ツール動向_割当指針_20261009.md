## 1. 使い分けの軸（先にこれ）

| 軸 | 意味 | 社員への当て方 |
|---|---|---|
| **A. 俯瞰・提案型** | 状況を見て「こうした方がいい」と持ち帰る | ミックス判断・週次材料・改善提案・参謀相当 |
| **B. 定期実行型** | 合図（時間／イベント）で同じ手順を回す | 取込点検・UI更新・健全性・定型検収 |
| **C. 実装・リポジトリ型** | コード／CLI／Git／Mac 権限が要る | スクリプト改修・フロー実装・代行指揮 |
| **D. 対話・指揮型** | 松野と会話しながら方針・例外・秘密ゲート | 本線の右腕（候補外） |

**松野の好み（2026-10-09）**: ChatGPT Bot／Grok Bot のように、**定期だけでなく俯瞰して提案してくる**ところが面白い → 割当時は A を軽視しない。B だけの体と、A＋B の体を意図的に分ける。

```text
同じ仕事を複数ツールにフル自動化しない。
社員フォルダの条件（合図・権限・報告）はツール移行でも変えない（Phase I）。
定期ジョブの本番実行は、特定エージェント（Claude Code / Codex / Cursor）にロックしない。
可能なら GitHub Actions（＋必要なら Graph／API）を本線にし、どのエージェントでも同じ入口を触れる形にする。
FlowForge は設計図・見える化。実行本体を FlowForge 単体に寄せない。
```

### 実行基盤の優先（2026-10-11 追記・松野方針）

| 優先 | 置き場 | なぜ |
|---|---|---|
| **1（本線）** | **GitHub Actions**＋リポ内スクリプト | クラウドで時間起動。ツール依存が薄い。どのエージェントでも同じ workflow／Secrets を辿れる |
| 2（保険） | Mac launchd | Graph／クラウドが落ちたとき・Mac専用処理 |
| 設計図 | FlowForge（AIオートメーション） | きっかけ・手順の見える化。実行エンジンにはしない |
| 将来の検討 | Claude Code Routines / Codex 等 | **GHA が難しいとき**の候補。社員条件は変えず、実行先だけ差し替え |

例: 211 返信案内下書き係 … 07:30 本線は `jarvis-reply-draft-211.yml`（GHA）。FlowForge の「どこで起動」も GitHub Actions に揃える。
