## 第1段階 — ビルダーで全体構成を固める

俯瞰的に社員を当てはめる場。

| やること | メモ |
|---|---|
| 部門・社員を並べて編成を見る | 足りない役割は**新しいエージェントを追加**しながら相談 |

## 第2段階 — AIオートメーションで1体ずつ作り込む

第1段階でフォルダ＋`flow.md` 叩き台が付いたら、1体ずつ FlowForge に載せて磨く。

| やること | メモ |
|---|---|
| 社員を **1体ずつ** | 同時に多体をフル磨きしない |
| Flowforge で動き（フロー）を作る／磨く | 例フローを型の参考にする。叩き台 `flow.md` を正として写す |
| 「ここを検討した方がいいか」を相談 | Jarvis がフローを見ながら磨き上げ |
| `flow.md` 先頭に **FlowForge URL** を書く | registry `flowforge_url` も更新 → status sync |

**禁止ツール**: **kintone**（使う予定なし）。台帳・案件は Todoist／OneDrive／KURASHIFT／Drive／jarvis-dashboard。FlowForge が kintone を出したら即差し替え（[`15_`](15_FlowForge全体系_進捗_20261010.md)）。

**実行の本線（2026-10-11）**: 定期ジョブは **GitHub Actions を優先**（特定の Claude Code／Codex／Cursor スケジューラにロックしない）。FlowForge は設計・見える化。詳細は [`07_実行ツール動向_割当指針`](07_実行ツール動向_割当指針_20261009.md)。

あわせて埋める: `CLAUDE.md` / `AGENTS.md` / `README.md` / **`TASK.md`** / `config/` `input/` `output/` `tests/` / 必要なら `.env`（[`05_機密とenv二層`](05_機密とenv二層_20261009.md)）／`agents_registry.yaml`・索引。  
共通規格・BCP: [`30_共通Agentフォルダ規格_BCP`](30_共通Agentフォルダ規格_BCP_20261017.md)。

## ハブ作業の手順（両段階をつなぐ）

1. **第1段階**でビルダー編成を固める（Phase A および部門追加時）
2. `_template/` をコピーして部門下に `NNN_名前/` を切る（IDは登記簿で採番）
3. **同一ターン**で `flow.md` 初回叩き台を埋める（Mermaid＋ステップ。空のまま禁止）＋ Builder／索引／permissions
4. **第2段階**で Flowforge ノード作成・磨き → `flow.md` 先頭に URL を書く＋ registry 更新
5. 登記簿・`00_チーム索引.md`・`config/agent_team_permissions.yaml`（`can_do`／サイトPWなら `site_logins`）を更新。合図・報告は `CLAUDE.md` §2／§4（運用メタは `config/agent_team_ops.yaml`）→ **`jarvis_agent_team_status_sync.py` を実行** → `agentTeam.json` を push（ダッシュ「権限」「運用」タブ）
6. 動いて Slack に届くまでを **1体分**やりきる（Phase H の型）
