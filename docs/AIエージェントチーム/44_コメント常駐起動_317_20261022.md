## 冗長の3層

| 層 | 内容 | 実行場所 |
|---|---|---|
| L0 | Todoist Webhook 受信 | Vercel（既存） |
| L1 | 拾い・Ack・分類 | Mac／stale 時 GHA |
| L2 | 許可リスト AI 処置 | Mac Local Agent／Cloud（枠あり） |

- heartbeat: `sync_meta.comment_dispatch_heartbeat_at`（約10分無更新で stale）
- 停止: `JARVIS_COMMENT_DISPATCH_DISABLE=1`／`JARVIS_COMMENT_DISPATCH_FAILOVER=0`
- Mac 間隔: launchd **300秒**
- **夜間除外（JST）**: 既定 **0:00〜6:00** は Mac／GHA とも処理スキップ（Mac は quiet heartbeat のみ）。変更: `JARVIS_COMMENT_DISPATCH_QUIET_START`／`END`、無効: `JARVIS_COMMENT_DISPATCH_QUIET_DISABLE=1`
- Hobby Vercel `*/5` Cron は使わない（GHA ping 型）
- **GHA 冗長の実態（2026-10-23 週次レビュー）**: GHA schedule は混雑で間引かれ、`*/5` でも実測 **約4〜5時間おき**。cron は毎正時を避けた **15分刻み・JST 6–24時**（`7,22,37,52 0-14,21-23 * * *`）に変更。冗長は「Mac 長時間停止の保険」でありリアルタイムではない
- GHA 冗長は Mac の `.jarvis_state` を持たない。FB の二重 Ack は **👀／✅ リアクション有無**で防ぐ（`has_handled_reaction`）。副次スクリプトは Mac venv が無ければ実行中の python で起動。`pyyaml` を workflow で導入。`CURSOR_API_KEY` は手動 `phase_b=true` のときだけ渡す
- **要対応（人）**: Slack Bot が **#report 未参加**（`not_in_channel`。10/23 時点で全実行で失敗）→ #report で Bot を `/invite`。未参加のままだと #report の FB スレ拾いは動かない
- Todoist 返信 404 は **Jarvis 未共有の松野個人 PJ のタスク**（owner トークンでは見える）。松野名義では返信しない方針のため失敗扱いせず見送り。Ack が要る PJ は Jarvis に共有する
- **#report 連投防止（2026-10-23）**: 未処理メモ集合の fingerprint（`sync_meta.comment_dispatch_slack_fp`）が変わったときだけ投稿。同一バックログは再掲しない。強制: `JARVIS_COMMENT_DISPATCH_SLACK_REPOST=1`。掃除: `scripts/jarvis_comment_dispatch_slack_cleanup.py`
