## 1. いま判断はどこでやっているか

```
Grok S1（物件調査・聞く/保留/見送り）
        ↓ 取込 → KURASHIFT deals
114 物件一次判定係（振分）
        ├─ A 自動 …… 松野判断なし → 511／Tier3
        ├─ B 要人 …… Slack #consult に Yes/No カード ← ★ここが本線
        └─ C 報告のみ …… Slack #report ダイジェスト
511 問合せ送信準備係
        └─ B で Yes のあと → 第一問合せ送信（estate）
```

| 誰 | 役割 |
|---|---|
| **Grok S1** | 調査本体・`聞く`／`保留`／`見送り`・handoff |
| **114** | レーン振分＋ `#consult` / `#report` 投稿 |
| **松野** | **B のときだけ** Yes（問合せする）／ No（見送り） |
| **511** | Yes 後の送信実行。追加のチャット確認はしない |

松野が判断するのは **B レーンのときだけ**。Yes＝その案件の第一問合せ了承。

正本（詳細）: `docs/AIエージェントチーム/23_物件進行ゲート_Grok調査_20261012.md`  
社員: `114_物件一次判定係` · `511_問合せ送信準備係`

## 2. Slack チャンネルの分け方（分類ごと）

複数の AI（AI社員チーム／将来の Grok Bot）が **同じ分類のチャンネルに並んで報告**する想定。

| ch | 用途 | 誰が上げるか（現行） |
|---|---|---|
| **`#consult`** | 松野の判断が要る（見送る／進める／方針相談） | 114 の Bカード、511 の失敗1行、Grok 定型の要ボス |
| **`#report`** | できたこと・完了・Cダイジェスト・日次／週次 | 114 の A/C、Grok 定型報告、他社員 |
| **`#ops`** | 連携障害・健全性・アプリ修正まわり | 315 等、Grok 定型の ops |

物件の「問合せする？見送る？」は **必ず `#consult`**。雑談・壁打ちは Grok チャットのままでよい。

## 3. `#consult` に出しているレポート内容（Bカード）

実装: `scripts/jarvis_property_gate_lib.py` の `format_b_card()` / `format_judgment_card()`。

### ヘッダ（位置づけ）

```
【114・物件一次判定】Bレーン（要人判断）— 要あなたの判断
調査=Grok S1 → 振分=114 → Yes後=511 ／ ※BotチャットでもCursorでもない

*{物件タイトル}*
理由：{レーン理由} ・ listen={聞く|…}
*判断軸*　土地値率 … ／ 利回り 表面 … ／ 想定 …
*ハザード*　{ステータス一行}
```

### 本文セクション（モバイル優先・等幅表は使わない）

| 節 | 入れるもの |
|---|---|
| **■ 概要** | 価格・土地値率・利回り（表面／想定）・所在 |
| **■ 土地値の評価** | 路線価×面積・率・クリア／惜しい／未達 |
| **■ 利回りの評価** | 表面（マイソク）と想定（S3／ペルソナ） |
| **■ 物件** | 土地・建物の要点 |
| **■ ハザード（足切り）** | 総合／洪水・高潮・急傾斜・内水・未着なら明示 |
| **■ 判定材料** | 聞く/保留・問合せ経路・score・掲載URL |
| **■ 判断** | Yes（問合せする）／ No（見送り）／ 全文HTML のラベル付きリンク |

Yes/No は **アプリ内ボタン**が本線（`action_id` → consult-action → 511）。成功時はカードが ✅／❌ に置換される。  
Bot／Signing 未設定時は **署名URLボタン**に自動フォールバック（ブラウザで判定。カードの自動置換はアプリ内本線時のみ）。  
予備として短縮 URL（`/api/g/y|n/{deal_id}`）も context に残す。  
詳細はログイン不要の全文ページ `/api/g/d/{deal_id}`。

### Yes / No のあと

| 操作 | 結果 |
|---|---|
| **Yes** | `re_deal_inquiry_send` → Mac job worker → estate 第一問合せ。結果を `#consult` に1行 |
| **No** | deal を見送り（`passed`）。再調査しない |

未判断の B は 1日1回 `#consult` にまとめてリマインド（`jarvis_property_gate_remind.py`）。

## 4. Grok Bot（Hawk）側で揃えてほしいこと

Slack が Grok から見えるようになったあと／それまでの Drive 経路:

### A. いますぐ使える経路（Slack 未接続でも可）

Drive inbox に定型 MD → Jarvis が Webhook 投稿:

```
---
action: slack_report
channel: consult
source: hawk
bot: ホークアイ（参謀）
kind: 物件判断相談
title: （物件名）見送りか問合せか
target: jarvis
---

# （物件名）— 要ボス判断

- 見どころ（土地値率／利回り／ハザード）: …
- 推奨: 問合せする / 見送り / 保留
- 理由（3行以内）: …
- 参照: deals URL または全文リンク（分かれば）
```

| channel | いつ |
|---|---|
| `consult` | 物件の見送り／問合せ／方針を松野に聞くとき |
| `report` | 調査完了サマリ・日次／週次 |
| `ops` | 連携・Bot 障害メモ |

正本: `docs/AIエージェントチーム/17_Grok定型報告_Slack_20261010.md`

### B. Slack 直投稿できるようになったら

- **同じ `#consult`** に上げる（チャンネルを新設しない）
- ヘッダに発信元を明示: `【Grok・ホーク】` または `【Grok・不動産部長】`（114 の `【114・物件一次判定】` と並ぶ）
- 判断軸は AI チームと同じく **土地値率・利回り（表面／想定）・ハザード** を先に出す
- Yes/No ボタンは 114/511 本線があるので、Grok 側は **相談・推奨・材料** に寄せてよい（二重の送信トリガを作らない）

### C. やらないこと

- 秘密・トークン・Webhook URL を MD／チャットに書かない
- Yes なしの対外問合せ送信（送信は Jarvis／511）
- `#consult` 以外への物件判断の散逸

## 5. Hawk への依頼（今回）

1. 本メモを読み、**判断場所＝Slack `#consult`（B）／レポート型＝上記セクション** を Grok チーム Instructions／ルーティンに反映候補として取り込む
2. Slack 接続作業は Grok Bot 側で継続（Jarvis は Webhook／inbox 経路を維持）
3. 物件判断・松野相談は、チャットだけに閉じず **`channel: consult` の定型**（または将来の直投稿）へ寄せる
4. 反映したら inbox または参謀室で「読んだ／Instructions に入れた」と一言（Drive で可）
