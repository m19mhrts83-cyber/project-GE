## 困ること（だからやらない）

| やり方 | 困る点 |
|---|---|
| フォルダ名を `【運用】111_…` に改名 | registry `path`・Drive写し・既存リンクがずれる |
| 状態ごとにフォルダを移す | 同上 |

**フォルダ名（`NNN_名前`）は状態で変えない。**

## 部門直下の並び（確定）

部門フォルダを開いたときの先頭2つ:

| 番号 | ファイル | 役割 |
|---|---|---|
| **00** | `00_状態ボード.md` | 配下社員の運用状態（一番上・一目用） |
| **01** | `01_部門.md` | 部門の役割・索引リンク |

`00_状態ボード.md` は registry から生成。手編集より **sync スクリプト**を正とする。

## 状態変更は提案が先（必須）

作業の結果として status を上げ／下げるとき（例: 定時が動いた→`運用確認`、意図OK→`運用`）:

1. **先にチャットで報告・提案**する（「〇〇なので `運用確認` に上げてよいですか？」）
2. 松野の了承後にだけ registry／マーカーを変える
3. 同一ターンで「運用確認に戻して」等と明示されたときだけ、提案省略して実行＋1行報告

**禁止**: 成果が出たからといって無言で `運用` や `運用確認` にする（315教訓 2026-10-11）。

## 必須運用（了承後・作成時）

どのAIツール（Claude Code / Cursor / Codex / GenCode / Grok 経由の Jarvis 等）でも:

1. （提案了承済みで）`agents_registry.yaml` の `status` を直す（または新規行を足す）
2. 索引を必要なら直す
3. **必ず同期を実行**:

```bash
cd ~/git-repos && ~/selenium_env/venv/bin/python scripts/jarvis_agent_team_status_sync.py
```

これで: 社員マーカー ↔ 部門 `00_状態ボード.md` ↔ README接頭辞 ↔ Drive写し ↔ **Jarvisダッシュ `apps/jarvis-dashboard/data/agentTeam.json`** が揃う。

ダッシュ UI: https://jarvis-dashboard-amber.vercel.app/agent-team （本番反映は JSON の commit＋push）。  
作業フローの作り込みは Cursor インブラウザの FlowForge（ログイン **m19m**）。ダッシュは状況確認＋深リンクのみ（iframe 埋め込み不可）。
