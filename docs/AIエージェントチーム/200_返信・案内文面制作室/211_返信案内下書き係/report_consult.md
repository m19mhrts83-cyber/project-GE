# 報告と相談 — 返信案内下書き係（211）

更新: 2026-10-11

## 役割分担（人が見る場所）

| 何か | どこ | 役割 |
|---|---|---|
| **運用の完了知らせ（本線）** | Slack `#report` | 「朝便が終わった／下書きがある／承認待ち」をここで受け取る |
| **方針の迷い・見積Bなし** | Slack `#consult` | 人が決める材料だけ短く |
| **起動失敗・Webhook失敗** | Slack `#ops` | 運用異常 |
| **下書き本文の正本** | OneDrive `4.送信下書き.txt` | 文面そのもの（Slackには全文を載せない） |
| **作業トラッキング** | Todoist（オーナー確認／進行中） | 補助。Slackの代わりにしない |
| **夜の横断確認** | Jarvis Dashboard | 補助 |
| **伴走中の詳細** | Cursor チャット | 定常運用の正ではない |

111（パートナー連絡整理）と同じく、**残す知らせの正は Slack**。

## いつ送るか

| 条件 | 行き先 |
|---|---|
| 下書きを1件以上保存した／承認待ち・見積B待ちがある | `#report`（成功時のみ） |
| 対象0件・失敗なし | **送らない**（111と同型） |
| 起動失敗・取込失敗・Webhook失敗 | `#ops`（要約1通） |
| From例外・見積B未確認・文面方針の判断 | `#consult` |

## 必須項目（報告）

- 係名: 返信案内下書き係
- 件数: 起案N／対象外N／見積B待ちN
- 社名（パートナーフォルダ名まで。本文全文は書かない）
- 正本: `4.送信下書き.txt` に保存済みか
- 次: 人が確認 → 「これで送ってOK」は **別フロー（送信）**。本フローは送信しない
- 失敗: なければ「なし」

## 文面サンプル

```
【報告】返信案内下書き係・朝便
・起案: 2（LEAF／ミニテック）
・見積B待ち: 0
・正本: OneDrive 4.送信下書き.txt 保存済
・次: 人が確認。送信はこの報告ではしない
・失敗: なし
```

```
【相談】返信案内下書き係
・決めてほしいこと: GrandoleI 202号の見積Bが無い。起案を止める／文面のみ進める？
・材料: 5.やり取り.md 2026-10-10 ミニテックスレ
・急ぐか: 朝便内なら今日中
```

## 実装メモ

- 投稿本体: `scripts/jarvis_slack_webhook_post.py --channel report`
- env: `SLACK_WEBHOOK_AI_TEAM_REPORT`（111で配線済・2026-10-10）
- Phase1: 手動パイロット成功後に1通テスト投稿
- Phase3: launchd 完了時に自動投稿
