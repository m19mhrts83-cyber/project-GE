# 機密・実行権限の持たせ方（二層）

**更新**: 2026-10-09  
**位置づけ**: AIエージェントチーム作戦の留意事項・運用ルール（いけとも型・DX渡しやすさ込み）

## 方針（確定の思い）

| 層 | 置き場 | 役割 |
|---|---|---|
| **社員（実行）** | 各社員フォルダの **`.env`** | その社員に渡した実行権限の APIキー／パスだけを置く。実行時はここを参照 |
| **マスター** | `~/git-repos/.env.jarvis_private` | **プライベート Jarvis の正本**。変更・追加があったら **必ずここにも反映・同期** |

Jarvis はマスターを失わない。社員 `.env` は「その体が動くために必要な最小セット」。

## やること

1. 社員に実行権限を渡すとき → 当該フォルダに `.env`（または `.env.local`）を作る  
2. キー名・値を追加／変更したら → **同じ内容を `.env.jarvis_private` に追記・更新**（マスター同期）  
3. Git には **値を入れない**。追跡するのは `.env.example`（キー名と説明のみ）  
4. MD／Slack／Todoist／チャットに秘密の値を書かない  

## やらないこと

- マスターだけ更新して社員 `.env` を放置（またはその逆）したまま実行を続ける  
- 全社員にマスター全文をコピーする（権限の最小化に反する）  
- 社員 `.env` を Git／Drive 写し／DX 配布 zip に平文で同梱する  

## DXメンバー等への提供を見据えて

後から「社員フォルダ一式」を渡せるよう、フォルダ型は揃える:

```
{id}_{名前}/
  README.md      … 一目
  CLAUDE.md      … 役割・合図・権限・報告（秘密の値は書かない）
  TASK.md        … 今回の依頼・完了条件（BCP引き継ぎ用）
  flow.md
  AGENTS.md
  config/ input/ output/ tests/ scripts/  … 共通規格（秘密は置かない）
  .env.example   … 必要なキー名のみ（値は空 or ダミー）
  .env           … 実値（ローカルのみ・gitignore）
  logs/
```

詳細: [`30_共通Agentフォルダ規格_BCP`](30_共通Agentフォルダ規格_BCP_20261017.md)

渡すときは **`.env` を除く**か、相手用にキーだけ説明した example を付け、実値は別経路（相手の秘密管理）で渡す。

## Jarvis の動作（エージェント向け）

| トリガー | 動作 |
|---|---|
| 社員に API／ログインを渡す・足す | 社員 `.env` ＋ **マスター同期**（片側だけにしない） |
| 同上・サイトID／PWを渡す | 加えて `config/agent_team_permissions.yaml` の `site_logins` を更新 → sync → ダッシュ「権限」タブ反映（`jarvis-agent-team-permissions.mdc`） |
| 社員フォルダを新規作成 | `_template` から切り、`.env.example` を用意。権限 YAML に `can_do` |
| DX／他者への配布話 | `.env` 除外・example のみ、と確認する |

正本の秘密ルール全体: `.cursor/rules/jarvis.mdc`（`.env.jarvis_private`）。本ファイルは **エージェントチーム固有の二層**を足す。  
権限俯瞰: [`25_実行権限一覧_20261015.md`](25_実行権限一覧_20261015.md) · YAML `config/agent_team_permissions.yaml`。
