# Grok Bot 対応・ミックスアップ識別（2026-10-10）

**目的**: AI社員のうち **Grok Bot と同系統の仕事**を一目で見分け、ミックスアップ（並べて比較・取捨）の先を特定する。  
**正本キー**: `agents_registry.yaml` の `mixup_kind` / `grok_counterpart` / `builder_tag`  
**Grok組織**: `config/grok_bots_registry.yaml`（ダッシュ `/agent-team` の「Grok Bot」「対応表」タブへ投影）  
**運用正**: [`03_Grok混成_ミックス運用_20261009.md`](03_Grok混成_ミックス運用_20261009.md)

## 識別の見方（印）

| 印（メモ・Builder名・表） | 意味 |
|---|---|
| **〔Grok:◯◯〕** | その Grok Bot／部署と同系統。ミックス先の片側 |
| **〔ミックスレーン〕** | GrokとAI社員を**比較する側**（特定Botの代替ではない） |
| （印なし） | Grok同型なし。Jarvis／Slack／既存Mac本線の社員 |

| `mixup_kind` | 意味 |
|---|---|
| `mac_twin` | **実行の正＝Grok**（判断・文案・許可後送信）。AI社員は **見守り・検収・補給・停滞見回り・材料整形・Slack**（同じ仕事の二重実行はしない） |
| `lane` | 400室。両系統の材料を並べて取捨するレーン |
| `none` | 対応Grokなし |

**やらない読み方**: 〔Grok:S1〕＝S1を置き換える、ではない。**並べて比較する相手**。最終採用は Jarvis／松野。

### D. ダッシュ対応表の3面（`/agent-team` → 対応表）

投影は **片側欠落も行として出す**（`jarvis_agent_team_status_sync.py` → `agentTeam.json`）。

| `side` | ダッシュ表示 | 中身 |
|---|---|---|
| `paired` | 対応あり | AI社員＋Grok（`mixup_kind`≠none） |
| `ai_only` | **Grok対応なし** | AI社員のみ（印なし・`none`） |
| `grok_only` | **AI社員対応なし** | Grok Bot のみ（registry に対応社員なし） |

フィルタ: すべて／対応あり／Grok対応なし／AI社員対応なし。件数は `mapping_counts`。

連絡・文面・品質・家計ガード・俯瞰UIの多くは **Jarvis／Slack本線**（`ai_only`）。必要なら411経由で材料化。
