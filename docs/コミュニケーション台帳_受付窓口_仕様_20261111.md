# コミュニケーション台帳の受付窓口 — 受け付け形式の仕様（2026-11-11）

ボット（Grok など）が台帳に直接登録するための窓口。ここで受け付けたものは「受付の表」`comm_intake` に入るだけで、台帳本体 `comm_items` への本登録は `jarvis_comm_hub.py ingest-intake`（取込ゲート → 名簿への当てはめ → 分類）が行う。

- メール（Grok部長日報）はそのまま続ける。まずはメールと直接登録を並行で使い、同じ内容が届くかを見比べる（松野さん方針 2026-11-11）
- 窓口は書くだけ。ボットは台帳を読めない（応答は受け付けた件数と id だけ）

## 呼び方

- `POST https://<Jarvis Dashboard>/api/comm-intake`
- ヘッダー: `Authorization: Bearer <受付窓口の鍵>`、`Content-Type: application/json`
- 鍵は送り手ごとに別（`COMM_INTAKE_KEYS` = `grok:<鍵>,grokmail:<鍵>` の形。復旧窓口と同じ作り）。送り手（`source_bot`）は鍵から決まる

## 本文

1件ならそのまま、まとめるなら `{"items": [ … ]}`（最大20件）。1件でも形が崩れていれば全体を断る（`index` で何件目かを返す）。

```json
{
  "bot": "grok",
  "bot_item_id": "bucho-20261111-01",
  "kind": "property",
  "occurred_at": "2026-11-11T08:30:00+09:00",
  "title": "東郷町 戸建て 新着",
  "summary": "駅徒歩12分・築22年。要確認",
  "refs": { "url": "https://…", "partner_folder": "102_ミニテック" },
  "source": "Grok部長日報"
}
```

| 項目 | 必須 | 決まり |
|---|---|---|
| `bot` | 任意 | 書くなら鍵の送り手と同じ名前（違えば 400） |
| `bot_item_id` | 必須 | ボット側の一意キー。`[A-Za-z0-9._:-]` 1〜128字。同じキーの再送は受け付け済みとして成功（冪等） |
| `kind` | 必須 | `partner`／`property`／`inquiry`／`self`／`agent`／`skim` |
| `occurred_at` | 必須 | ISO 8601。未来（24時間超）・400日より前は断る |
| `title` | 必須 | 1〜300字 |
| `summary` | 任意 | 4000字まで |
| `refs` | 任意 | JSON オブジェクト（4KB まで）。`party_id`／`partner_folder`／`partner`（名前）があれば名簿に当てはめる。`thread` があれば同じ話題としてまとめる鍵に使う |
| `source` | 任意 | 80字まで（例: `Grok部長日報`） |
| `topic` | 任意 | 種類の印。`[a-z0-9_]` 1〜40字（例: `daily_report`／`property_research`／`repair_vendor`／`dev_card`）。`kind=agent` でも `repair_vendor`・`dev_card` は台帳で「やること」（work_status=new）になる |
| `needs_action` | 任意 | `true`／`false`。台帳で「やること」にするかを個別に決める（topic より優先） |

## 応答

| 状態 | 意味 |
|---|---|
| 202 `{"ok":true,"accepted":n,"ids":[…]}` | 新しく受け付けた |
| 200 `{"ok":true,"accepted":n,"ids":[…]}` | すべて受け付け済み（再送） |
| 400 | 形式の誤り（`error`・`index`） |
| 401 | 鍵が違う |
| 413 | 本文が 64KB を超えた |
| 429 | 1分あたり30件を超えた（`Retry-After: 60`） |

## 台帳への取り込み（ingest-intake）

- いつ: 昼の台帳書き込み GHA の後（`Comm intake (bots) → comm_items`）と、Mac の予備（13:40・21:10）。両方で走っても `external_id = intake:<bot>:<bot_item_id>` で1行にまとまる。失敗しても本線は止めない
- 取込ゲート（入れずに `status=rejected` と理由を残す）: `skim`／不明な `kind`／`title` が空／日時が読めない／銀行・認証系（認証コード・ワンタイム・パスワード・振込・残高・銀行 など）
- 分類: `kind` → `category`（partner／property／inquiry／self／agent）。`channel=other`、`account=bot:<bot>`、`direction=inbound`、tags に `bot:<bot>`・`kind:<kind>`
- 対応状況: `agent`（ボットの日報など）は `no_action`、それ以外は `new`（Todoist の仕分けの入り口に乗る）

## メール経由の中継（既定オフ）

`jarvis_grok_bucho_mail_apply.py` が読んだ日報を、`JARVIS_GROK_INTAKE_RELAY=1` かつ `COMM_INTAKE_URL`／`COMM_INTAKE_KEY` があるときだけ窓口に送る（`bot_item_id = mail:<Gmail の message id>`、`kind=agent`、`refs.via=mail`）。送り手は `grokmail` の鍵を想定（直接登録の `grok` と見分けて並行の見比べに使う）。`--mark`・YAML の反映はこれまでどおりで、中継に失敗しても止めない。
