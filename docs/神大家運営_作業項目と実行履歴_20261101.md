# 神大家運営：事前の項目設定と項目別の実行履歴

2026-11-01 松野さんの指示に基づく、本人用の運用。Codex・Claude Code・Cursorで共通利用する。

## 作業の進め方

1. 着手前に松野さんと目的・成果物・完了条件・作業項目を相談し、案件IDと項目IDを設定する。項目名には何ができたら終わりかを書き、見積・承認状況も履歴へ記録する。
2. エージェントが確認できた実行内容・結果・根拠は、セッションの区切りに項目別で記録する。過去のチャット全体を毎回再解析しない。
3. 本人の手作業・時間・判断など確認できない情報は、質問を項目に紐づけて記録してから、チャットでまとめて本人に聞く。回答を得たら質問ID付きで追記する。質問の作成だけで本人へ通知されたとは扱わない。
4. 作業終了時に結果・次の作業を記録し、Dashboardへ同期する。追加項目・範囲変更は元の履歴を消さず追記する。
5. 振り返りはDashboard「神大家運営 → 作業履歴」。案件を選び、作業項目を開く。未回答の質問と時間未記録を確認する。

## 記録の正本

共通の履歴IDを持つ追記記録を、OneDrive P806 `工数管理/work_history.json` とJarvis用Supabase `sync_meta.kamiooya_work_history` で同期する。同名MDはスクリプトで自動生成する閲覧用。手で二重入力しない。Dashboardで追加・訂正した記録はSupabaseへ即時保存し、CLIの `--push` 実行時にOneDriveへ取り込む。Q&A用Supabaseには書かない。

秘密、会員情報、会話全文、ローカルパスを履歴へ貼らない。要点とHTTPSの成果物・根拠リンクを残す。同期失敗でもローカルの記録を保持し、再同期する。正本を別名にコピーして同時編集しない。

時間は `owner_confirmed`（本人確認済み）、`estimated`（推計）、`agent_elapsed`（エージェント処理）、`unrecorded`（不明）を分ける。無人処理・CI待機・離席を本人稼働として計上しない。不明は0分にしない。見積8hは実績ではなく、Pro料金と開発費も別。請求判断は本人が行う。

時間などの訂正は `log --supersedes 旧記録ID` に理由と訂正値を記録する。旧履歴を残し、Dashboardの集計では訂正後だけを数える。

## エージェント用コマンド

リポジトリルートから実行。`--push` の前に `.env.jarvis_private` を値を表示せず読み込む。各変更の `--event-id` は一意に決め、通信失敗後の再試行では同じIDを使う。

```bash
python scripts/jarvis_kamiooya_work_history.py plan \
  --project project-id --title '案件名' --estimate-minutes 480 \
  --item 'prepare:対象と完了条件を決定' --item 'implement:実装と動作確認'

python scripts/jarvis_kamiooya_work_history.py --push log \
  --project project-id --item prepare --status done \
  --event-id unique-record-id --summary '確認内容と結果' \
  --evidence 'https://github.com/owner/repo/pull/123'

python scripts/jarvis_kamiooya_work_history.py --push ask \
  --project project-id --item implement --summary '本人の手作業時間は何分でしたか？'

python scripts/jarvis_kamiooya_work_history.py --push answer \
  --project project-id --item implement --question-id 上で返った記録ID \
  --actor 松野 --summary '本人回答をそのまま短く記録' \
  --minutes 20 --time-kind owner_confirmed

# 同期だけ再試行（新しい実績は追加しない）
python scripts/jarvis_kamiooya_work_history.py --push show
```

記録と同期はエージェントが実行する。チャットやPC全体を常時自動収集する機能ではない。古い作業の時間を推測で埋めない。本人はエージェントとの会話で回答するほか、Dashboardから直接回答・追記・時間訂正もできる。

## Dashboardから記入する

保存成功後はページを再表示して最新の記録・集計を読む。入力不備・保存失敗の場合は画面の入力を保持する。

- 作業項目を開き「作業記録を追加する」で、作業日・内容・時間（分）・時間区分を記入する。時間不明は空欄。状態・根拠リンクも任意で追記できる。
- 実行記録の「時間・記録を見直す」で訂正する。元の記録は残し、最新の訂正だけを時間集計に使う。本人時間とエージェント処理時間を選び分ける。
- 未回答質問の「この質問に回答する」で本人の回答を記録する。
- 同時追記は読取版番号を確認して再試行し、記録を失わない。同じ実績へ競合する訂正があれば上書きせず確認を促す。CLIも旧スナップショットで画面入力を消さず、IDでマージする。
- オフラインではCLIを `--push` なしで記録し、次に通信可能なとき `--push show` で双方向同期する。同期前のローカルだけを見て画面入力が未保存と判断しない。
