## 噛み砕き：銀行とアプリのズレ／「毎月返済額の固定」とは

用語メモ: ここでいうのは **借入元本（契約金額）のロックではない**。  
銀行が決めている **毎月の返済総額（約定返済額）を、金利が変わっても同じ金額のままにする** 話。

### 銀行（オリックスなど）の動き

1. 毎月、だいたい同じ金額を払う（例: 262,928円）
2. 金利が上がっても、しばらくは **払う総額は同じ**
3. 変わるのは中身だけ  
   - 金利↑ → 利息の割合↑・元金の返済↓  
   - 金利↓ → その逆  
4. だから銀行の残高は、このルールで減っていく

### アプリ（いま）の動き

1. 「契約上の毎月返済額」に 262,928 を入れても
2. **金利履歴を足すと、月額そのものを作り直す**ことがある  
   （例: 262,928 → 245,031 や 294,599 など）
3. すると毎月の元金返済額が銀行と違い、**残高がだんだんずれる**
4. いまは「実績返済」で銀行の返済後残高を1行入れて直している（実績アンカー）

### たとえ

- 銀行: 「毎月の給料天引きは固定。金利が変わっても天引き額は同じ。中身の配分だけ変える」
- アプリ（いま）: 「金利が変わったら、天引き額自体を計算し直す」
- 実績アンカー: 「ズレた結果だけ、銀行の残高に合わせてリセットする」  
  → 効くが、**金利改定のたびにまたズレうる／直す手間が残る**

### 開発者に頼みたい本丸（①）

「契約上の毎月返済額」が入っている借入では、

- 金利改定 → **返済総額は変えない**
- 変えるのは **利息と元金の内訳だけ**

というモード（＝毎月返済額の固定／ロック）がほしい。

### いま自分でできること／できないこと

| | できる | できない（＝要望） |
|---|---|---|
| 金利の記録 | 金利履歴に行を足す | — |
| いまの残高を銀行に合わせる | 実績返済（アンカー）1行 | ずれの再発を防ぐ |
| 毎月の支払額の期間管理 | だいたい1つだけ | 272,539→300,746 のような履歴 |

4. **残高の as-of 明示** — 「現在残高（計算基準日: YYYY-MM-DD）」を一覧・詳細に表示
5. **割賦（手数料込）商品タイプ** — 太陽光のような「総支払÷回数」型

## B-RATE-4 合算金利（残高加重）

実装: `apps/trade-desk/lib/bRate4.ts`（`blendLoanRate` / `buildBRate4Rows`）  
表示: `/realestate`・`/realestate/properties`

### 式

\[
r_{\mathrm{eff}} = \frac{\sum_i (B_i \times r_i)}{\sum_i B_i}
\]

- \(B_i\): 各ローンの残高（`balance_jpy`）
- \(r_i\): 各ローンの金利％（`rate_pct`）
- 対象: ③-C と同じ物件紐づけ（`loansForProperty`）。教育・車・太陽光などプライベートは物件に載せない
- 残高または金利が欠けるローンは合算から除外（件数を UI 注記可能）
- **正味** = 表面利回り（満室年収÷本体価格）− \(r_{\mathrm{eff}}\)
- **本担保のみ**: 参考列（諸費用を除いたスコア最高の1本）

月返済加重は採用しない（金利コスト比較は残高加重が標準。月額は合計を別表示）。

### キャラメル検算例（JSON 時点）

| ローン | 残高 \(B\) | 金利 \(r\) |
|---|---:|---:|
| 本担保（セゾンF） | 44,497,227 | 2.55% |
| 諸費用（オリコ） | 948,717 | 2.675% |

\[
r_{\mathrm{eff}} = \frac{44497227\times 2.55 + 948717\times 2.675}{44497227+948717} \approx 2.55\%
\]

（諸費用の構成比が小さいため本担保に近い。内訳の構成％は UI に表示）
