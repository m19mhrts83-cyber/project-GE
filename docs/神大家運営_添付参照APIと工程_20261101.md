## 今回の実装

- `supabase/functions/community-attachments/index.ts`: 外部依存なしの専用Edge Function。Raimo backendのみ添付セッションを発行可能。ブラウザはユーザーIDと期限を署名した8時間tokenだけを保持し、一覧/クリックごとにRaimoへ現状照会。meta一覧は原本・署名URLを含まない。原本はDBの添付IDから固定bucket/pathを引いて署名する。リクエストが渡すStorageパスは使わない。CORSは指定Raimoのみ、全応答no-store。
- 正本Raimo API YAMLに `/auth/attachment-session` と `/internal/attachment-user-status` を追加。前者は既存のemail/password_hash/statusで認証し、外部へパスワードを送らない。後者はサーバー専用secretで認証し、id/status/roleのみ返す。
- 正本app.jsと公開コピーに添付インデックス・原本参照を追加。パスワードは既存のRaimoへ一時的に送るだけで、新しい永続保存はしない。tokenはメモリのみ。ログアウト/別ユーザー再ログイン後に古い応答で状態が上書きされない。添付障害で通常ログインや本文閲覧を止めない。
- 公開スクリプトは専用proxy secretをRaimo backendにだけ注入する。ブラウザの設定APIへ返さない。Supabase service_roleはEdgeのサーバー内のみ。
