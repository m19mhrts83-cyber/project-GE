- 原本取込: PR212/main、3,671件のhash/path照合一致、非公開Storage。

## 確認した事実

原本取込後の認証経路の最終確認で、Raimoの既存`GET /admin/users`が未認証のリクエストに200を返し、usersの`password_hash`が含まれることを確認した。値自体は出力・記録していない。既存login/attachmentSessionのDB照合は入力のpassword_hashとの一致であるため、添付Edge単体の401試験では認証経路全体の安全性を保証できない。

先行の「会員限定閲覧の基盤完成」という報告は確認範囲不足。ユーザーへ訂正済み。第三者の取得・不正利用の有無は未確認であり、漏えいがなかったとは断定しない。

## 実施した最小限の緊急措置

- Edgeの`memberReadsEnabled`を本番でfalseに固定。session/index/list/openを503で拒否し、新規発行と発行済みtokenの両方を止める。新しい権限・接続は作らない。以前の署名URLは最大60秒で失効する。
- Raimo既存のlistApprovedUsers/listPendingUsers/attachmentSessionの先頭checkをfalseにし、本番定義へ反映。60ルート中この3ルート以外は保存前の定義を維持。未ログインの2一覧が400でusersを返さないこと、Edgeのindex/sessionが503でtokenを返さないことを確認。
- 原本、コメント、会員データは削除・変更しない。既存の認証情報そのものの変更・会員への連絡は行っていない。ユーザー一覧/承認画面は暫定的に取得不可になる。
- 運営の事前承認ルールにある「情報漏えいの拡大を防ぐ最小限の緊急措置」として先行対応。恒久的な認証改修・資格情報更新・対外通知の判断は別に整理する。

## 再開条件・次の優先工程

1. 既存Raimo API全体の認証・認可と、ユーザー/管理者操作・会話/会員データ・パスワード変更/再設定の経路を監査する。今回止めた3ルートだけで全体の修復完了とはしない。
2. パスワード/認証用データをレスポンスへ返さず、クライアント申告のuser_id/roleを権限根拠にしない方式へ修復する。
3. 過去に公開されていた可能性のある資格情報の扱い・更新・必要な連絡を本人と判断する。無断のパスワード変更や会員への送信はしない。
4. 修復後に添付用sessionSecretを更新して旧tokenを失効させ、承認済み本人/他人/未承認/退会/匿名と管理者権限の回帰試験を行う。その後にだけ閲覧を再開する。
