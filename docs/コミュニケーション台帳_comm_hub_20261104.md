## 行の決まり

| 列 | 決め方 |
|---|---|
| `party_id` | `partner:<フォルダ名>`（例 `partner:P102_ミニテック`）。kind はフォルダ番号の百の位（1管理/2修繕/3保険/5金融/6入居者/7学習/8神大家/9代理店） |
| `external_id` | md 由来は `md:<sha1>`（フォルダ・日時・見出しチャネル・件名・要約から）。111 の候補と同じ式なので並走時に重複しない |
| `direction` | 見出しが「自分から…」なら outbound（「相手から返信」でも自分発信本文なら outbound） |
| `work_status` | outbound と 14 日より古い受信は `done`、新しい受信は `new`、111 の未返信候補は `needs_reply`。人が閉じた状態は上書きしない |
| `ingest_status` | 既存のノイズ判定（`is_noise_mail` / `is_chat_noise`）に当たれば `excluded`、他は `ready` |
| `source_ref` | md のパスと見出し（全文の正本へ戻る道） |

## 閉じ残しの戻しと突き合わせの数え方（2026-11-10）

- **閉じ残し**: triage 側が sent／todoist／skipped／info で閉じても、台帳 `comm_items` は `needs_reply` のまま残っていた（11/10 時点 57 件中 19 件）。`link-pending` の最後に `close_resolved` を足し、つながる triage（`comm_links` と `triage_items.comm_item_id` の両方、lane を問わない）が**すべて**閉じていれば戻す。sent・todoist が1つでもあれば `done`、skipped・info だけなら `no_action`。pending・未知の状態・triage 行が見つからないリンクが1つでもあれば触らない。リンクが無い `needs_reply` も触らない。昼 GHA でも毎回走る
- 一覧で確かめる: `python scripts/jarvis_comm_hub.py link-pending --dry-run --list`
- **突き合わせ**: `python scripts/jarvis_comm_hub.py reconcile`（読み取りのみ）。a = /partner の未返信（lane=partner・pending）、b = 台帳 `needs_reply` のうち partner の pending triage につながる行。general の pending につながる分は `b_general` として別に出す（以前は b に混ざって「不一致」になっていた）。一致 = a == b かつ `a_unlinked`・`stale`（閉じ残し）・`reverse`（partner の pending なのに台帳が done 等）が 0
- 11/10 の1回限りの整理: 19 件を戻した（done 4・no_action 15）。`needs_reply` は 57 → 38。逆向きの 1 件（P809「10月グルコンの融資情報一覧について」：/partner では未返信、台帳では done）は直さず残している
- 毎朝 9 時のスケジュールタスク `comm-hub-phase1-check` は、最初の `gh run list` に許可ルールが無く、無人の許可待ちで止まっていた（11/9・11/10）。止めて、照合は Claude 側で `reconcile` を使って行う
