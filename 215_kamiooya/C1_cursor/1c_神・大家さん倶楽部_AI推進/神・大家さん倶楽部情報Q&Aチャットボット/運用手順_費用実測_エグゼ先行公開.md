# 運用手順: エグゼラウンジ先行公開中の費用実測

作成: 2026-11-05
目的: 今村さんへ送った概算（Gemini 月約5万〜18万円／1日1,000回×30日）を、先行公開中の実績で確かめる。
「実際の利用回数と費用を計測し、その実績で見積もり精度を上げる」約束への対応。

## 何が測れるようになったか

| 項目 | 取り方 | 精度 |
|------|--------|------|
| 質問数（週ごと・通常／意味） | `app_qa_search_events` を週次集計（件数上限なし） | 実数 |
| 利用者数（期間・週ごと） | 同上の `user_id` の重複なし件数 | 実数（週は通常・意味の多い方） |
| 意味検索の Gemini 費用 | 要約1回ごとの `usageMetadata`（入力・出力・思考トークン）× 公開単価 | 実測 |
| 通常検索の Gemini 費用 | Raimo 側で Gemini を呼ぶためトークンが取れない。件数 × 単価目安（$0.02〜0.04） | 想定 |
| 実請求額 | AI Studio「kamiooya-qa」（課金アカウント「神大家Q&A」）を手で確認 | 実額 |

通常検索の費用は「実請求 −（意味検索の実測分）」で逆算できる。週次で突き合わせると、通常検索1問の実単価も出せる。

## 反映手順（1回だけ）

1. Supabase の SQL Editor で `apps/kamiooya-qa-web/supabase/migrations/20261105_qa_usage_metering.sql` を実行
2. Edge Function を再デプロイ
   - `supabase functions deploy semantic-search --no-verify-jwt`
   - `supabase functions deploy qa-analytics --no-verify-jwt`
3. Raimo に新しい `app.js` / `index.html` を反映（運営分析画面に「費用の実測（週次）」が出る）
4. 任意: 単価や為替が変わったら Edge の環境変数で上書き
   - `GEMINI_PRICE_INPUT_USD_PER_M`（既定 0.5）
   - `GEMINI_PRICE_OUTPUT_USD_PER_M`（既定 3.0。思考トークンも出力単価）
   - `USD_JPY_RATE`（既定 150）

**順番を守ること**: migration より先に semantic-search を出すと、トークン列が無いため意味検索のログ記録が失敗する（検索自体は動く）。qa-analytics だけ先に出した場合は、画面に「週次集計が未設定です」と出るだけ。

## 毎週やること（5分）

1. 運営分析 → 「開始日（実測期間）」に先行公開の開始日を入れて「再取得」
2. 「費用の実測（週次）」の表を確認する
3. AI Studio の当週請求額と見比べる
4. 見るポイント
   - 1問あたり実単価（実請求 ÷ 成功質問数）。試算の 1.5〜6円と比べる
   - 通常／意味の比率
   - 実請求と画面の「Gemini 費用」のズレ（大きければ通常検索の単価目安を見直す）
   - 前払い残高（月上限3万円・アラート 5,100／15,000／27,000／30,000円）

## 今村さんへの共有

資料の打ち出しはせず、今村さんにも運営分析画面を直接見てもらう（2026-11-05 松野さん方針）。
- 運営分析は「管理者」以上に表示される。今村さんのアカウントを管理画面のユーザー一覧で「管理者に設定」すれば見られる（コード変更不要）
- 管理者はユーザー承認など他の管理機能も使えるようになる点に注意
- 画面で見られる項目: 期間、成功質問数、利用者数、Gemini 費用、1問あたり単価（試算 1.5〜6円と並べて表示）
- AI Studio の実請求額は画面に出ないため、ズレが大きい月だけ松野さんから補足する

## 注意

- 現在の利用者は運営メンバーと松野さんのみ。先行展開でメンバーを追加していく。運営の動作確認の質問も数に入るため、「開始日（実測期間）」を先行展開の開始日にして見る
